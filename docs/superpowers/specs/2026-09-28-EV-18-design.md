# EV-18 — Render the resolved control-plane URL as the attended /rc:login input placeholder

Design spec settled by the EV-18 Council deliberation (three generator rounds:
owner, principal, designer; Skeptic attack with all objections closed by tests
that ran; consolidator synthesis: no open judgment, no open objections). This
document is the single hand-off to the implementing owner; nothing in it reopens
what the deliberation closed.

## Problem

The attended `/rc:login` URL prompt bakes the resolved control-plane URL into
its title and passes `ui.input` only the title argument. The documented
`placeholder` argument is dropped at two seams:

1. `index.ts:~107` — `RemoteControllerDeps.inputPrompt` is declared
   `(prompt: string) => Promise<string | undefined>` (one param).
2. `index.ts:~973` — the entry wiring forwards only the title:
   `inputPrompt: (prompt) => requireCtx().ui.input(prompt)`.

Additionally, `src/pi-sdk-on.ts:31-32` carries a comment asserting
"Real signature: input(title: string, placeholder?: string)" — a **factually
false** claim about the installed host: the installed
`@earendil-works/pi-coding-agent@0.87.1`
`dist/core/extensions/types.d.ts:75` declares
`input(title: string, placeholder?: string, opts?: ExtensionUIDialogOptions): Promise<string | undefined>`,
with `ExtensionUIDialogOptions = { signal?: AbortSignal; timeout?: number }`
(`types.d.ts:37-42`). Both facts were verified by two seats and re-verified by
the Skeptic.

## Binding constraints (Phase-1 run rulings, applied verbatim)

- **Surface copy**: the prompt title stays byte-unchanged — it keeps
  `[${resolved}]` and the existing keyless consent sentence; **no copy key is
  added, changed, or removed** (FLLWUP-41 untouched).
- **State and field naming**: the widened dependency names its second parameter
  `placeholder`; the dep becomes
  `(prompt: string, placeholder?: string) => Promise<string | undefined>`.
  No other state, field, or status is renamed.
- **Error and empty-state text**: no new error or empty-state copy;
  empty-submit / typed-override / Escape-cancel semantics stay behaviorally
  unchanged.

"Resolved" keeps EV-15's meaning: env → `piRemote.serverUrl` setting → stored
credential → literal default (`https://relay.jumpseat.sh`), via the shared
`resolveServerUrl` (`src/server-url.ts`).

## Changes

### 1. Widen the dependency (`index.ts:~107`)

```ts
inputPrompt: (prompt: string, placeholder?: string) => Promise<string | undefined>;
```

Annotate it (JSDoc) with the real SDK signature
`input(title, placeholder?, opts?: ExtensionUIDialogOptions)` — the dep stays
two-param (it is pi-remote's seam; pi-remote never supplies `opts`), but the
annotation must cite the real three-param signature.

### 2. Pass the placeholder at the attended URL prompt (`index.ts:~672`)

Pass `resolved` as the second argument. The title template literal is **not
edited at all** — the call gains a second argument; the string stays
byte-identical to today's
`Control-plane server URL [${resolved}]:\nPress Enter to enroll this host against ${resolved}, or type a different URL to override:`.

### 3. Forward both arguments at the entry wiring (`index.ts:~973`)

`inputPrompt: (prompt, placeholder) => requireCtx().ui.input(prompt, placeholder)`.

### 4. Replacement-confirm prompt stays URL-less (`index.ts:~705`)

`deps.inputPrompt("Press Enter to replace the existing credential, or Escape to keep it.")`
keeps exactly one argument. No placeholder.

### 5. Reconcile the vendored `ui.input` declaration (`src/pi-sdk-on.ts:31-32`)

Declare the full three-param real signature with provenance, mirroring the
sibling `confirm` member's precedent (line 33-34 already declares its optional
members citing the EPIC-6/FLLWUP-39 declare rule, route (a): declare, do not
omit):

- `input(title: string, placeholder?: string, opts?: { signal?: AbortSignal; timeout?: number }): Promise<string | undefined>`
- Inline the structural opts shape exactly as `confirm` does — **do not** import
  a named `ExtensionUIDialogOptions`; it does not exist in the vendored file.
- Provenance citation: installed `@earendil-works/pi-coding-agent@0.87.1`
  `dist/core/extensions/types.d.ts:75`.
- **Floor**: the "Real signature:" comment may not continue to assert a
  two-param signature. Declaration widening is the agreed path.

### 6. Test plan

All in `test/`, extending the existing suites' patterns (dependency-injected
`ExtensionAPI` stand-in; no module-level mutable state).

a. **Four-tier placeholder matrix (red today)** — extend the tier matrix at
   `test/index.test.ts:~1866-1888` to capture `(title, placeholder)` and assert
   `placeholder === expected` byte-equal across all four resolve tiers (env →
   setting → stored credential → literal default). The matrix closure must
   declare `placeholder?` (or capture via rest) — a required-second-param
   closure fails `TS2322` even against the widened option type.
b. **Title byte-equality (green guard, hardened)** — in the same matrix, assert
   the full title equals the exact keyless literal with `.toBe()` per tier —
   whole-literal equality, not `startsWith`/`toContain`. This is the FLLWUP-41
   regression guard (the URL never leaves the rendered surface).
c. **Entry-wiring forward test (red today; load-bearing)** — drive the real
   `export default` with a fake `pi` whose `registerCommand` trap captures the
   `rc:login` handler; invoke with a fake command context whose `ui.input`
   records `(title, placeholder)`; assert the pair across a chosen tier. No
   existing test observes an argument reaching `ctx.ui.input` (the harness
   tier matrix bypasses the entry wiring at `:973` entirely). This is the only
   in-repo seam that pins the actual forward.
d. **Typed-override pin** — acceptance 3's matrix update must actually pin the
   typed-input branch (a non-empty `inputPrompt` return enrolls against the
   trimmed typed value). **No test in the suite drives this branch today** —
   every existing `inputPrompt` stub returns `""` or `undefined`. Empty
   submission (`""` → resolved URL) and Escape (`undefined` → no driver
   constructed, no discovery fetch, no tunnel POST, credential file untouched)
   are already pinned (T2/A1 at `:1781`; T8 at `:1994`); do not regress them.
e. **Replacement-confirm pin** — with an existing credential forcing the
   replacement path, assert the captured second argument is `undefined` for
   the confirm prompt.
f. **Harness option type** — widen `HarnessOptions.inputPrompt`
   (`test/index.test.ts:~151`) to
   `(p: string, placeholder?: string) => Promise<string | undefined>` in the
   same PR. Existing no-op stubs (`async () => ""`, `async () => undefined`)
   remain assignable unchanged — only the option type and the new matrix
   closure change.
g. **Vendored-signature pin** — after the reconciliation, a three-arg call
   against the vendored `PiExtensionContext["ui"]["input"]` compiles (today it
   fails `TS2554`); the provenance comment cites `types.d.ts:75`.
h. **Observation obligation (designer P3)** — the wiring-forward test (c)
   keeps passing with two-arg calls after the declaration widens to
   three-param; it is not an arity probe and must not be treated as one.

Gates: `bunx tsc --noEmit` exit 0; `bun test` green (332 pass / 7 skip baseline
before this card; the only expected non-pass remains the Windows-gated
credential-ACL skip on non-Windows runners).

## Residuals (name both in the PR description and the card record)

1. **Installed-host placeholder-discard** (card acceptance 6): installed pi
   0.87.1's `ExtensionInputComponent` discards `_placeholder`, so no greyed
   in-box render occurs on the installed host; the title is the rendered
   fallback until a host honors the signature. EV-19 verifies this by real-host
   observation (designer prediction P-E).
2. **Future-host double/triple render**: on a host that honors the documented
   signature, the resolved URL renders three times (bracket in title, consent
   sentence, greyed placeholder). Converged as convention-consistent, not a
   comprehension defect; any trim is post-EV-19 scope. Designer prediction P-F
   (placeholder clear-on-type on a honoring host) is a labeled hypothesis,
   carried in the card record only — not a gate.
