# EV-5 Design Spec — JSONL History Replay and Resync

Card: `EV-5` (EPIC-1) — "JSONL history replay and resync"

Status: settled by Council deliberation (3 rounds, converged ≤ cap), Skeptic
attack (O1–O10), consolidation, and product-owner rulings A/B1/B2 (binding,
applied). This file is the **complete** design. If anything here is
ambiguous, the design is wrong — so it is not. The owner reads only this
file. The card's four open objections (U1, U2, U3, U4) and three closed-red
corrections (O1, O3, O6) are carried here as explicit gate/acceptance
targets — closing them by green tests on the PR is what step-9 verification
checks.

## 0. What the card is

Implement `src/history.ts`: replay the active JSONL branch through
`translate.ts` on connect and on resync, framing the batch with `replay:
true` and deterministic event ids derived from entry id + content hash +
frame ordinal, then answer with the `pi.resync.done` CUSTOM terminator up to
the highest replayed seq. PI-SPEC §5 is the intent; §2 keeps history an
extension-side concern answered from the host's JSONL, never from server
state.

As part of the **same PR**, apply three facilitator-authored, evidence-cited
prose-sync amendments to `docs/PI-SPEC.md` per the EV-1 Q3 + EV-4 Q1
precedent (no separate spec card, no steward):

1. **§5.2 step 3** — replace `compaction → MESSAGES_SNAPSHOT + CUSTOM
   (pi.context.compaction)` with `compaction → CUSTOM (pi.context.compaction);
   MESSAGES_SNAPSHOT emitted at init, carrying the active branch`
   (ruling A; cited O9, O10).
2. **§5.3 resync_done line** — replace the literal `{ type: "resync_done",
   uptoSeq }` with `{ type: "CUSTOM", name: "pi.resync.done", value: {
   uptoSeq } }` (ruling B1; cited O8).
3. **§5.3 clarifying sentence** — append one sentence: "Inbound resume and
   resync control frames are runtime-validated by `transport.ts`'s
   `parseInbound` against a discriminated union (resume, resync, AG-UI event,
   ack-only); control frames do not surface to the `onInbound` AG-UI
   consumer. The relay server's role is unchanged: it relays these frames
   opaquely per §5.3 and §7.3." (ruling B2; cited O6).

The card's own acceptance section is already amended in `council/cards/EV-5.md`
(facilitator-authored, evidence-cited). **`§2` is NOT amended** — its literal

## 1. The settled design (binding)

### 1.1 Replay walk (history.ts)

`src/history.ts` exposes `replayActiveBranch(…): ReplayResult` where
`ReplayResult = { frames: ReplayFrame[]; resyncDone: { uptoSeq: number } }`.

1. Read the active branch via `ctx.sessionManager` (`getBranch()` from the
   current leaf) where possible; fall back to direct JSONL reading for large
   tails. Both paths normalize to `translate.ts`'s `JsonlEntry` surface
   (additive kinds per §1.3), honoring compaction (`retainedTail` /
   `firstKeptEntryId`) and `branch_summary` so the replay is the active
   branch only — no orphaned or pre-compaction entries.
2. **Emit exactly one `MESSAGES_SNAPSHOT` at init**, before the walk begins,
   carrying the active-branch message list as
   `{ type: "MESSAGES_SNAPSHOT", messages: [{ role, content: string }, …] }`
   (AG-UI `MessageSchema[]`; each `Message` a `{role, content: string}` for
   the user/assistant text the active branch contains at init time). This is
   the destructive state-reset a stock AG-UI client expects — never
   in-stream (ruling A).
3. Walk the entries through `translate.ts`'s `translateJsonl` (unchanged
   mapper, entry-level), synthesizing **one RUN_STARTED/RUN_FINISHED pair per
   past run** by feeding `agent_start`/`agent_settled` PiEvents through the
   LIVE mapping (fresh `createState` per run with a deterministic `runId`).
   Past-run boundary = a `user` message entry through the last
   assistant/toolResult before the next `user` entry. A degenerate
   single-run session = one pair, no special-case.
4. **Compaction points emit `CUSTOM {type:"CUSTOM", name:"pi.context.compaction",
   value:{pi:"session_compact", data:{summary, firstKeptEntryId,
   tokensBefore}}}` only** — no MESSAGES_SNAPSHOT in-stream (ruling A).
5. **STEP_* frames are OMITTED entirely** in replay (JSONL has no turn
   entries; RUN pairs delimit the same boundaries — settled, O7 closed-green).
6. Frame the whole batch with `replay: true` and deterministic event ids (§1.2).
7. Terminate with `{ type: "CUSTOM", name: "pi.resync.done", value: { uptoSeq } }`
   where `uptoSeq` equals the highest replayed seq (ruling B1; honesty: a
   mid-replay send that returns null must NOT produce a lying resync_done —
   §1.6).

### 1.2 Deterministic frame id + replay flag

- **Frame id = `fnv1a(entryId + "\u0000" + contentHash + "\u0000" + frameOrdinal)`**
  (FNV-1a 32-bit hex). Frame-granularity: a single JSONL entry yields
  multiple frames; entry+contentHash alone would collide and the client would
  dedupe-drop later frames. `frameOrdinal` = the frame's ordinal within the
  entry's translation (a fresh counter starting at 0 per entry). settled (all
  three seats converged).
- **`replay?: boolean` is a FRAME-level optional field** on the transport
  frame type — widen `AgUiFrameLike` (`AgUiFrame & { id?: string; replay?:
  boolean }`). The envelope stays exactly `{v, seq, ack, frame}` (4 keys;
  O2 closed-green — the exact-key test is not relitigated).
- Live frames: UUID `id` stamped by the injected `newId` (EV-3); **replay
  frames: deterministic id present, `replay:true`, never overwritten** (the
  EV-3 `newId` stamping leaves a pre-existing `id` untouched).
- **Gate target (U3 / closed O3):** a replayed frame round-trips with
  `replay:true` and its deterministic id intact; the envelope still has
  exactly 4 keys. Replay-twice yields byte-identical emission.

### 1.3 Additive translate.ts per-entry kinds

§5.2 names `tool_result`, `custom`/`custom_message`, `bashExecution` for
replay, but `translate.ts`'s `JsonlEntry` union models only
`message|compaction|model_change|thinking_level_change|session_info`. EV-5's
PR touches `translate.ts` **additively** for these per-entry kinds:

- `tool_result` → handled inside message handling (not a standalone kind);
  maps to `TOOL_CALL_RESULT` per §4.
- `bash_execution` → `CUSTOM` passthrough in EV-5 (full semantic mapping
  deferred to FLLWUP-3).
- `custom`/`custom_message` → `CUSTOM` per §4 escape-hatch discipline.

These additions are additive — no existing mapping or test changes. The
mapper stays pure and entry-level (O4 closed-green, O5 closed-green).

### 1.4 runId derivation (per past run)

- **runId = `run-<fnv1a(sessionId + "\u0000" + firstUserEntryId)>`**, fresh
  `createState` per past run, one RUN_STARTED/RUN_FINISHED pair per run
  (settled).
- **Gate target (U4):** when a past run's first *kept* entry is not a `user`
  message (e.g. it opens with an assistant message after compaction cutting
  the user turn), the runId derivation must **not crash and stay stable** —
  it must fall back deterministically (e.g. to the first kept entry's id in
  place of a missing user entry id) so the same session replays to the same
  runId and RUN pair every time. Test asserts: two replays of the same JSONL
  produce the same runIds; an edge JSONL whose kept tail opens with a
  non-user entry produces a stable, non-crashing runId.

### 1.5 Inbound discriminated union (transport.ts, ruling B2)

Harden `parseInbound` (currently validates only `typeof frame.type ===
"string"` — the O6 cast hole). The `frame` slot widens to a discriminated
union, the envelope stays exactly 4 keys:

```ts
type InboundFrame =
  | AgUiFrame                          // today's shape, validated identically
  | { type: "resume"; deviceId: string; lastAckedSeq: number }
  | { type: "resync"; fromSeq: number }
  | null;                              // heartbeat / ack-only
```

- `AgUiFrame` shapes validate as today (existing O2/O8 tests stay green).
- resume/resync validate their structural fields (deviceId string,
  lastAckedSeq/fromSeq finite numbers).
- Anything matching none of the four → rejected as `protocol_violation` (the
  existing closed 5-value EV-3 reason taxonomy; **no new taxonomy**).
- **Control frames never reach `onInbound`.** `resume`: logged debug-level,
  updates the inbound watermark (`inboundSeq`), never surfaces to the footer
  and never reaches `onInbound`. `resync`: triggers an injected
  `onResync(fromSeq)` callback — a seam of the same shape as `rearm`
  (transport is a protocol state machine with injected seams); `fromSeq` is
  a `number` (the seq to replay from; `null`/`0` defaulting to "replay all").
  EV-8 sequences `onResync(fromSeq)` → `history.resyncActiveBranch({fromSeq})`
  → replay batch + `pi.resync.done` (B2 general rule).
- **Gate targets (U2 / closed O6):** parseInbound accepts each of the four
  union members; rejects everything else as `protocol_violation`; resume
  updates the watermark without surfacing to `onInbound`; resync invokes the
  injected callback **exactly once** per inbound resync control frame.

### 1.6 Resync terminator honesty

`resyncDone.uptoSeq` equals the maximum replayed seq. If a `send()` returns
null mid-replay (drop-with-signal while not live), do **not** emit a lying
`pi.resync.done` — surface the drop honestly (the transport already signals
it; EV-8 renders terminality). Test asserts the terminator's `uptoSeq` equals
the max replayed seq, and no resync_done is emitted when a mid-replay send is
dropped.

### 1.7 Replay-twice dedupe (acceptance, tested)

Delivering the same replay batch twice yields identical ids, so client-side
dedupe by event id is sufficient. **Test:** run the replay twice over the
same fixture JSONL; the two frame sequences have identical `id` values, the
init MESSAGES_SNAPSHOT matches, and in-stream frames are byte-identical
(including the same deterministic runIds).

## 2. Emission contract (acceptance meaning, post-amendment)

| Point in replay | Emits |
|---|---|
| Init (before walk) | exactly one `MESSAGES_SNAPSHOT` — active-branch messages, no compaction summaries inside |
| Each message entry | message/step/tool events per §4 (STEP omitted — settle) |
| **Each compaction entry** | **`CUSTOM pi.context.compaction` only — zero MESSAGES_SNAPSHOT in-stream** (ruling A) |
| Per past run | one RUN_STARTED / RUN_FINISHED pair (deterministic runId, §1.4) |
| Each entry's frames | `replay:true` + deterministic id (§1.2) |
| End of batch | `CUSTOM {type:"CUSTOM", name:"pi.resync.done", value:{uptoSeq}}` (ruling B1) |

## 3. Gate / acceptance targets (owner clears locally; Skeptic re-runs at step 9)

Each of the four open objections and three closed-red corrections is a named
gate target the PR must demonstrably close by green test:

- **U1 / O1 — MESSAGES_SNAPSHOT presentation:** one init snapshot with the
  active-branch messages (no summaries inside `messages`); zero
  MESSAGES_SNAPSHOT in-stream at compaction; one CUSTOM
  `pi.context.compaction` per compaction entry; active-branch-only snapshot;
  replay-twice identical.
- **U2 / O6 — parseInbound discriminated union:** four members accepted;
  non-members rejected as `protocol_violation`; resume updates watermark,
  not `onInbound`; resync fires injected callback exactly once.
- **U3 / O3 — `replay?: boolean` widening:** replay frame round-trips with
  `replay:true` + deterministic id; envelope stays exactly 4 keys; live
  frames unaffected.
- **U4 — runId edge:** non-user first-kept-entry past run does not crash and
  stays stable; same JSONL → same runIds on repeat.

Typecheck (`bunx tsc --noEmit`) and the full `bun test` suite (49 existing
green, kept) must pass. Tests use in-repo fixture JSONL sessions; no Mongo.

## 4. Explicit non-goals (from the deliberation record)

- Replaying **extra** live-pi event kinds not reachable from the JSONL
  (queue_update, bash_execution_update, auto_retry_*) — FLLWUP-3.
- Full semantic mapping of `bashExecution` — deferred to FLLWUP-3
  (passthrough CUSTOM here).
- The live path wiring (EV-8) and the footer `resyncing` state — EV-8's lane.
- §2 amendment or any portfolio-level wire-contract change — none (ruling B2).
- Working against server state — history answers from the host JSONL only (§2).
