# EV-8 — Command surface and lifecycle wiring

This is the settled design for EV-8, written up after the Council deliberation
(steps 2–6). It implements PI-SPEC §8: the entry point that registers the `/rc`,
`/rc:login`, `/rc:off` commands and the `session_shutdown` handler, subscribes
the live event path, and owns teardown. The product-owner rulings J1–J5
recorded on the card are binding and are folded in here verbatim in intent.

**Entry-point file.** The package's entry (`package.json` `"module": "index.ts"`)
is the repo-root `index.ts`. EV-8 implements that file. (The card's
`src/index.ts` phrasing refers to the entry point conceptually; `src/` holds
the leaf modules — this card turns the root `index.ts` from the stub
`console.log("Hello via Bun!")` into the extension.)

## 1. Architecture

Follow the `create*` factory pattern established by every leaf module:

- `export default function (pi: ExtensionAPI)` — a thin factory that resolves
  dependencies from the live pi context and delegates to a framework-agnostic
  `createRemoteController(deps)` returning `{ commands, reducer, onShutdown }`.
  `createRemoteController` is pure and testable with in-repo fakes; `default`
  wires only the pi SDK surface (`pi.on`, `ctx.ui.setStatus`, `ctx.ui.input`,
  command registration, `emitSessionShutdownEvent`).
- **All session-scoped mutable state lives in the factory closure** of
  `createRemoteController` — never module-level. A module-level tunnel would
  leak across a session switch on `new`/`resume`/`fork`/`reload`.
- `index.ts` is the **only** module allowed to hold this state. Do not add new
  mutable state to leaf modules. New pure helpers (the merge function, the
  SessionEntry→JsonlEntry adapter) may be added to leaf modules as pure,
  exported, individually-tested functions — no module-level mutable state.

`createRemoteController` owns (and duplicates nowhere else):
- the lifecycle FSM: footer state, `tunnelId`, the live `TranslateState`,
  the in-flight teardown promise, the consecutive-error counter, the epoch
  token;
- the rearm closure wiring (DELETE-old → optional one-silent-refresh →
  createTunnel) with rich-reason recording;
- `createTransport` wiring: `onEvent`→FSM, `onInbound`→injector,
  `onResync`→replay, `newId`, `sessionId`, plus the transient `disconnect`
  reference used to stop the dial loop on enrollment-terminal errors (J3);
- the two orphaned adapters (SessionEntry→JsonlEntry for replay; the
  `occurrence` stamp on outbound `pi.human_input` raise frames);
- the shared idempotent `teardown()`.

It does **not** duplicate: copy vocabularies (`tunnelReasonCopy`/`englishFor`,
`loginEnglishFor`, `ALREADY_LIVE_COPY`), frame construction (`translate` is the
only mapper), seq/ack/backoff/heartbeat/reconnect (`transport`), inbound
arbitration (`inject`), tunnel REST/discovery/refresh/401 policy (`tunnel`).

**One fresh `createTransport` instance per `/rc`.** This restarts `outboundSeq`
at 0 (`transport` only guarantees "never reset within the instance"). The FSM
drops stale events via the transport's own `order` ordinal (the merge's order
guard).

## 2. Footer model

The footer is the single host-visible status surface:
`ctx.ui.setStatus("pi-remote", sentence)` showing **exactly one of seven
states**, in lifecycle order: `off`, `not enrolled`, `authorizing`, `dialing`,
`resyncing`, `live`, `error` (spec §8; product-owner ruling EV-1 Q2).

- Every state change is a stated sentence resolved through
  `loginEnglishFor` — never a glyph ack, never a raw string, never an unkeyed
  concatenation. `setStatus("pi-remote", …)` is the **single footer writer**,
  called only from `createRemoteController`.
- On no active state (e.g. `off` with nothing else), the implementation may
  render the `status.off` sentence or call `setStatus("pi-remote", undefined)`;
  the choice must be consistent and tested. Prefer rendering the `status.off`
  sentence for a truthful footer.
- `createRemoteController` exposes a `reducer` (the footer FSM) so tests can
  drive status transitions without a live pi, plus the `setStatus` side effect
  is injected.

### 2.1 The merge function (J1, J4)

A single pure function, kind-first, order-guarded:

```
type FooterState = "off" | "not enrolled" | "authorizing" | "dialing"
                 | "resyncing" | "live" | "error";
function mergeTransport(footer, lastOrder, e: TransportStatusEvent, consec, N):
  { footer: FooterState, lastOrder: number, consec: number }
```

Rules, applied for a transport event `e`:

1. **Order guard.** If `e.order <= lastOrder`, return the input unchanged
   (stale/out-of-order event).
2. **`kind: "live"`** → `{ footer: "live", lastOrder: e.order, consec: 0 }`.
   This **clears a sticky `error`** (verified recovery — J1). A `live` event is
   emitted only after a successful WS open + one-time-token validation, so this
   is the system's recovery signal.
3. **`kind: "dialing"`:**
   - if `e.severity === "error"` (relay_unreachable / protocol_violation /
     url_expired): `consec = consec + 1`. If `consec >= N` →
     `{ footer: "error", consec }` (reason resolved per §3). Else →
     `{ footer: "dialing", consec }` **unless** the footer is already `error`,
     in which case keep `error` (sticky — dialing does not clear it).
   - if `e.severity === "resyncing"` (first_connect / reconnecting),
     non-error severity: `consec = 0`; keep `error` if already `error`, else
     `{ footer: "dialing" }`. **A first-dial `resyncing`-tagged event must
     render `dialing`, never `resyncing`** (kind-first, not severity-first).
4. **`resyncing` is never produced by `mergeTransport`.** It is a replay-overlay
   state owned by the replay path (§5.3). 
5. **Most-recent-wins across the live family** (`dialing`/`resyncing`/`live`):
   the newest transport event wins; only `error` is sticky until cleared by a
   `live` event or a user action (`/rc`, `/rc:off`, `/rc:login`).
6. **A transport `dialing` arriving mid-replay aborts the replay** and moves
   the footer to `dialing` (replay frames would drop via `send()→null`).

**N is pinned at 10 (J4), injectable as `ERROR_DIAL_THRESHOLD`** (default 10)
with constraints satisfied (N ≥ 2, injectable, deterministic). The `consec`
counter lives in the FSM, **independent of the transport's backoff counter**
(two different numbers). It resets on any non-error-severity event.

Non-transport writers write the footer as **direct FSM transitions, bypassing
`mergeTransport`**:
- `/rc` with no credential → `not enrolled` (sentence naming `/rc:login`).
- `/rc` start (proceeding) → reset `consec`/`lastOrder`, optimistic `dialing`.
- enrollment-terminal rearm error (J3) → `error` with the rich enrollment
  reason, immediately (does not wait for N).
- `/rc:off` and `session_shutdown` → `off`.
- `/rc:login` `onState` → `authorizing` on begin, `off` on terminal.

## 3. Rearm closure and enrollment terminality (J3 + Skeptic must-satisfy)

**The rearm closure is EV-8-authored** and passed as `transport`'s
`deps.rearm` (called once per dial attempt ≥ 2). It performs **DELETE-old →
optional one-silent-refresh → createTunnel** and returns `CreateTunnelResult`.

- On any thrown `TunnelError`, the closure **records the rich
  `TunnelError.reason`** in the FSM (`lastRearmReason`). Transport internally
  collapses all rearm failures to `relay_unreachable` (its `dialLoop` catch);
  **EV-8 must NOT rely on transport's reason** — it keeps its own.
- **Enrollment-class terminal errors (J3).** When the thrown `TunnelError` has
  `kind === "unauthenticated"` (reason `enrollment_expired`) or
  `kind === "forbidden"` (reason `enrollment_rejected`), the closure:
  1. stops the transport's dial loop (`transport.disconnect()` via a captured
     handle reference — disconnect is idempotent and id-stops the loop);
  2. transitions the footer **directly to `error`** carrying the rich
     enrollment reason's copy key (`tunnel.error.unauthenticated` /
     `tunnel.error.forbidden`) — NOT `relay_unreachable`, and WITHOUT waiting
     for the N-threshold;
  3. does not rethrow into transport's collapse (the loop is already stopped).
  The remedy line is `/rc:login` (comes free from the `tunnelReasonCopy` rows).
  Credential-still-present is unchanged: teardown never clears the credential.
- **Transient rearm failures** (control_plane_unreachable / server_error /
  validation) rethrow to the transport's normal reconnect loop. The footer
  reaches `error` via threshold-N in §2.1 if the condition persists, and the
  error line is resolved from `lastRearmReason` (preferring it over the
  collapsed `relay_unreachable`). **Transport terminality (dial forever) and
  credential terminality (stop on dead credential) are two separate seams** —
  the transient path keeps dialing forever, the enrollment path stops (J3).

## 4. Command behaviors

### 4.1 `/rc`

- `readCredential`; if `null` → footer `not enrolled` + one sentence naming
  `/rc:login`; **no `POST /tunnels`, no transport dial, no URL prompt**; return.
- Resolve server URL: **env > stored credential**. Never a URL prompt from a
  bare `/rc` (J2 — see §7). If neither exists, tell the user to run
  `/rc:login`.
- If enrolled but the access token is expired: perform **ONE silent
  `refreshAccessToken`** when a refresh token exists; on success persist the
  rotated credential via `saveCredentialAsync` (EV-7-owned keys) and continue;
  on no refresh token or refresh failure → `/rc:login` remedy + footer
  `not enrolled`, do not dial.
- If already `live` → print `ALREADY_LIVE_COPY` verbatim, footer unchanged,
  no second dial/subscribe, runId unchanged.
- **Proceed iff footer ∈ {`off`, `error`}.** On proceed: reset `consec` and
  `lastOrder`, optimistic `dialing`, `createTunnel` (first URL), create one
  fresh `createTransport`, `connect({url, expiresAt})`.
- Stated refusal (footer unchanged, no-op) iff `authorizing` / `dialing` /
  `resyncing` (dialing-in-progress sentence) or `live` (`ALREADY_LIVE_COPY`).
- Unenrolled → `not enrolled` + names `/rc:login`, zero `POST /tunnels`.

### 4.2 `/rc:off`

- **Was live** → teardown; footer `off`; lifecycle sentence printed.
- **Was not live** → print the **same** lifecycle sentence (a clean no-op, no
  "no-op"/"already"/"ignoring" wording; byte-equal to the after-a-live line).
- **DELETE failed** (`deleteTunnel` surfaces `teardown_failed`) → the failure
  is surfaced (`tunnel.error.teardownFailed`) but the footer **still lands on
  `off`**, not `error` (best-effort teardown; the local close is authoritative).
- Second `/rc:off` → shares the in-flight teardown promise; **zero additional
  `deleteTunnel`** calls.

### 4.3 `/rc:login` (J5)

- The login driver is entered **only from `off` and not enrolled**.
- If the FSM is in any non-idle state (`live`, `dialing`, `resyncing`,
  `authorizing`, `error`) → **refuse** with a single stated sentence:
  "close the tunnel first with /rc:off"; footer **unchanged**; login driver
  **not entered**.
- Otherwise: `createLoginCommand({...deps, onState})`; on
  `onState("authorizing")` → reducer `{kind:"authorizing"}`; on settle →
  reducer `{kind:"off"}` (success AND failure both return footer to `off`).

### 4.4 `session_shutdown`

- Registers through `pi.on("session_shutdown")` (or the extension's shutdown
  hook ≥ EV-7 precedent) for **every** reason (`quit`, `reload`, `new`,
  `resume`, `fork`). Each calls the shared `teardown()`.
- Idempotent with `/rc:off`.
- Print a single line ("remote tunnel closed") and set footer `off`.

## 5. Live path, replay, runId, occurrence, adapter

### 5.1 Live path

`pi.on` subscriptions registered once at the factory. Handlers gated on the
FSM being `live` (or `agent_start` on transport connected): pi event →
`translate(input, liveState)` → `transport.send(frame)` (drop-signal rendered
per transport `send()→null`). `onInbound(env)` → `createInjector` →
`sendUserMessage`/steer/followUp per inject.ts. `onResync(fromSeq)` → replay (below).

### 5.2 runId

EV-8 mints the live runId. On each `agent_start`: replace the live
`TranslateState` with a **fresh** `createState({ sessionId, runId:
crypto.randomUUID() })`; thread it through the fold until `agent_settled`, then
leave it for the next `agent_start`. Recreating per `agent_start` resets
`openMessages`/`eventOrdinal` so fold bookkeeping cannot leak across cycles.
- If a live frame arrives with no active run, lazily mint one.
- Replay **never touches** the live `TranslateState` (history.ts internally
  creates per-run `TranslateState` with deterministic `run-*` ids).
- `transport.send` stamps an `id` only when absent, so deterministic replay ids
  survive (§ `AgUiFrameLike.id` semantics).

### 5.3 Replay / resync

`onResync(fromSeq)` → read the active branch → normalize to `JsonlEntry[]` →
`history.replayActiveBranch({sessionId, entries})` → send each frame
(`replay:true`, deterministic ids) via `transport.send` → send
`resyncDoneFrame`. Footer overlay `resyncing` during the replay; back to `live`
after `resyncDoneFrame`; abort on a mid-replay `dialing` (§2.1.6).

### 5.4 SessionEntry→JsonlEntry adapter (EV-8 scope)

`history.replayActiveBranch` takes `JsonlEntry[]`, but the live pi SDK exposes
`SessionEntry[]`. **The adapter is EV-8 scope** (not a follow-up): a pure,
exported function (e.g. `sessionEntriesToJsonl(session): JsonlEntry[]`) isolated
in one file, with a **dedicated test**. The pi SDK `SessionEntry` type is **NOT
vendored** in this repo — the adapter is the single boundary that touches that
un-vendored shape, so keep the type reference confined to that one function and
declare a minimal structural local type at that boundary (do not import a
non-existent SDK path).

### 5.5 `occurrence` stamp (orphaned adapter #2)

`inject.registerPrompt({promptId, kind, prompt})` returns `{ occurrence }`
from its per-promptId counter. EV-8 calls `registerPrompt` alongside the
outbound `pi.human_input` raise (translate's `ui.confirm` CUSTOM frame) and
**stamps the returned `occurrence` onto that outbound frame's `value`**, so
inject's `handleApprovalResponse` can match `promptId` + `occurrence`
(`occurrence` 1 then 2 for the same `promptId`).

## 6. Teardown

One shared, idempotent, epoch-bumped `teardown()`, used by `/rc:off` and
`session_shutdown`:

1. bump the epoch/generation token (so any in-flight connect/rearm sees itself
   stale);
2. set FSM `stopped`;
3. `await transport.disconnect()` (idempotent; also halts enrollment-retry per
   §3);
4. capture `currentTunnelId` and `await deleteTunnel(...)` best-effort
   (swallow failures — but per 4.2 the DELETE failure is rendered as
   `tunnel.error.teardownFailed` without moving the footer to `error`);
5. footer → `off`.
- Concurrent second callers return the **same in-flight promise** (zero extra
  DELETE).
- **`clearCredential` is NEVER called.** The credential survives teardown
  (EV-2/EV-7 boundary).
- The rearm closure checks the epoch before work and after `createTunnel`
  lands; if the epoch moved, `deleteTunnel(freshTunnelId)` and bail. When a
  rearm lands a fresh `tunnelId`, `currentTunnelId` updates synchronously in
  the closure, so teardown deletes the right tunnel.

## 7. PI-SPEC §8 URL-prompt amendment (J2)

The product-owner ruling J2 amends §8's literal "/rc prompts once for a
control-plane URL if unset." The amendment rides EV-8's PR (facilitator-authored,
evidence-cited, in-scope prose-sync):

- **Behavior:** the URL prompt fires only out-of-band after `/rc:login`, never
  from a bare `/rc`. A user without a configured URL is told to run `/rc:login`
  (the remedy they need anyway).
- **No serverUrl-only credential store** is introduced. The durable home for
  the server URL is the full credential file written by `/rc:login` on success.
  Server URL resolution is env (`PI_REMOTE_SERVER_URL` or the
  `piRemote.serverUrl` setting) > stored credential > (out-of-band, via
  `/rc:login`).
- **Implementation:** update `docs/PI-SPEC.md` §8 with this correction
  (one prose sentence) in the same PR. Cite J2. This is the only PI-SPEC change
  EV-8 makes.
- FLLWUP-1's README sync carries the user-visible reflection.

## 8. Copy rows

Add **ten new rows to `login.ts`'s `loginEnglishFor`** table (single resolved
vocabulary; no new resolver — do not route footer copy through
`tunnel.englishFor`):

- **7 `status.*` rows** for the footer states: `status.off`, `status.notEnrolled`,
  `status.authorizing`, `status.dialing`, `status.resyncing`, `status.live`,
  `status.error` — each a stated sentence.
- **3 transport-error rows** for the reasons with **no rows anywhere today**:
  `tunnel.error.relayUnreachable`, `tunnel.error.protocolViolation`,
  `tunnel.error.urlExpired`. EV-8's merge maps `e.reason → key` for these; note
  `tunnel.ts`'s own `tunnelReasonCopy` already covers the tunnel-side reasons
  (enrollment/control-plane/server/teardown/validation).

Also resolve the command output lines (`/rc` unenrolled remedy, `/rc:off`
lifecycle line, `/rc:login` refusal line, session-shutdown line, dialing-in-progress
refusal) through `loginEnglishFor` (add rows as needed in the same table). All
footer copy and command output uses `loginEnglishFor`; never a raw string or a
glyph. Localization of these new rows rides the FLLWUP-4 localization seam (this
card only adds the English defaults).

## 9. hostMetadata / sessionName

Minimal closed `hostMetadata = { piVersion, platform, arch }`; `sessionName`
defaults to `basename(process.cwd())`.

## 10. Test acceptance mapping

All tests use in-repo fakes for the pi context and SDK surfaces — no relay, no
control plane, no Mongo. The 113 existing tests stay green (gates) and new
tests cover, at minimum (mapping to the card's acceptance + claims):

- `/rc` on an enrolled host ends `live` with frames flowing; second `/rc` while
  connected prints `ALREADY_LIVE_COPY` verbatim, footer unchanged, no second
  dial/subscribe, runId unchanged.
- `/rc:off` while live ends `off`, tunnel deleted once at the control plane; a
  second `/rc:off` is a clean no-op (zero additional DELETE).
- One test per shutdown reason (5): quit/reload/new/resume/fork with tunnel live
  and no `/rc:off` → disconnect + one DELETE + footer `off` + credential still
  present.
- No credential: `/rc` fails gracefully, output names `/rc:login`, footer `not
  enrolled`, zero `POST /tunnels`.
- Footer is exactly one of seven states; `error` derives only from the typed
  transport/tunnel stream; `resyncing` shown during replay.
- `/rc:login`: footer `authorizing` on driver begin, `off` on terminal (success
  AND failure); refusal (`close the tunnel first with /rc:off`) when live /
  dialing / resyncing / authorizing / error — driver not entered, footer
  unchanged.
- **merge unit tests (J1/J4):** N-1 then Nth consecutive error-severity dialing
  → `dialing` then `error`; a subsequent `live` resets to `live` (recovery);
  dialing-while-error keeps `error` (sticky); a first-connect
  `resyncing`-severity dialing renders `dialing` (kind-first); order guard
  drops stale events; resyncing overlay + live-drives-to-live.
- **Enrollment-terminal test (J3):** a 401/403 from `createTunnel` inside the
  reconnect rearm lands the footer `error` with the rich enrollment reason
  (`enrollment_expired`/`enrollment_rejected` remedy, not `relay_unreachable`)
  and stops the retry loop.
- **Teardown/rearm race:** controlled deferred rearm, `/rc` then reconnect so
  rearm awaits, `/rc:off` before it resolves, resolve rearm with a fresh tunnel
  → fresh tunnelId DELETEd once, no connect after teardown, footer `off`.
- `occurrence` stamp: 1 then 2 for the same `promptId`, resolves in inject (not
  `ignored`).
- SessionEntry→JsonlEntry adapter: pure, dedicated test.
- runId: fresh per `agent_start` cycle, distinct across cycles, live
  UUID-shaped; replay uses deterministic `run-*` ids.

## 12. Out of scope (do not do)

- No server/relay/control-plane implementation.
- No live re-enroll (`/rc:login` while `live` stays refused; flagged as a
  future card if ever wanted — J5).

  look-up).

- No change to the seven-state set or to leaf-module contracts beyond the
  additions above.
