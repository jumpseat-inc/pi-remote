# EV-15 — Default the control-plane URL to `https://relay.jumpseat.sh`

**Status:** settled design (Council deliberation, EV-15, EPIC-7). This document is the
handoff to the single owner. It does not derive a design; it records the one the
deliberation settled, as modified by the binding product-owner ruling of record
(step 6, job-13). Nothing here may be reopened by the implementer.

**Card goal:** Resolving the control-plane server URL with neither
`PI_REMOTE_SERVER_URL` nor `piRemote.serverUrl` set and no stored credential falls
back to `https://relay.jumpseat.sh`; the `/rc:login` URL prompt is retained as the
interactive override affordance and is pre-filled with the resolved value; a stored
credential's own `serverUrl` still wins over that default.

**Binding Phase-1 rulings applied throughout:**

- `state and field naming` — the constant is `DEFAULT_SERVER_URL`; the resolver is
  `resolveServerUrl`. Tier order is env → setting → stored credential → default.
- `surface copy` — exact prompt wording is owned by the design pass within the
  acceptance substrings. This delegation **does not authorize leaving the keyless
  boundary** (step-6 ruling).
- `error and empty-state text` — the `noServerUrl` removal is named in the PR
  description.

---

## 1. Single resolver home

New dependency-free module `src/server-url.ts` (mirrors the `copy.ts` precedent —
nothing imported, no cycle risk), with one suite per module convention:
`test/server-url.test.ts`.

```ts
export const DEFAULT_SERVER_URL = "https://relay.jumpseat.sh";

/** Total resolver. Tier order: env → setting → stored credential → DEFAULT_SERVER_URL.
 *  Always returns a non-empty trimmed URL. */
export function resolveServerUrl(input: {
  envUrl?: string | undefined;
  settingUrl?: string | undefined;
  credentialUrl?: string | null | undefined;
}): string;
```

- Emptiness is **trim-based**: `undefined`, `null`, `""`, and whitespace-only tiers
  are all absent and fall through to the next tier.
- Total return type `string` is what makes `noServerUrl` unreachable.
- `normalizeServerUrl` is **not** exported (no consumer outside the resolver;
  normalization is tested through `resolveServerUrl`).
- `resolveServerUrl({ credentialUrl: "" }) === DEFAULT_SERVER_URL` is pinned (the
  empty-credential case; see §7 for why the reader is tightened anyway).

## 2. Dep shape

`RemoteControllerDeps.serverUrl: string | undefined` (index.ts:89) is replaced by
two raw tiers:

- `envServerUrl` — `process.env.PI_REMOTE_SERVER_URL` passed through unchanged.
- `settingServerUrl` — `settingString("serverUrl")` passed through unchanged.

Env is still read at the entry only (DI discipline preserved; no env reads inside
`src/`). The full tier order lives inside `resolveServerUrl`, testable without env
mutation.

**Load-time tier stays explicit-only.** There is no collapsed load-time `serverUrl`
value anymore; the entry passes the two raw tiers and the controller resolves.
Nothing on the load path picks up the credential or the default (Acceptance 3 holds
structurally). The former `index.ts:856` collapse is gone.

## 3. The three runtime sites consult the one resolver

- **`rearm`** (index.ts:263): read `cred`, then
  `resolveServerUrl({ envUrl, settingUrl, credentialUrl: cred?.serverUrl })`. The
  gate narrows to `if (!cred)` — the `!serverUrl` half is dead. `enrollment_expired`
  (index.ts:265, 293) now always renders the resolved URL.
- **`rcCommand`** (index.ts:545): same resolver call; the `!serverUrl` branch
  printing `rc.serverUrlRequired` is **deleted**, and both copy rows go (English
  footer row login.ts:268, id overlay row copy.ts:73).
- **`rcLoginCommand`** (index.ts:610–617): read the existing credential **before**
  the prompt (move `readCredential` up), compute
  `resolved = resolveServerUrl({ envUrl, settingUrl, credentialUrl: existing?.serverUrl })`,
  then:
  - **Attended mode:** the prompt fires **unconditionally** (all four tiers),
    prefill reflecting the resolved tier. The post-change code branches on
    `serverUrl === undefined`, never on `!serverUrl` (the seam distinguishes them;
    O6's precision caveat).
    - `""`/whitespace submission → **accept the prefill**: enroll with exactly
      `resolved` (explicit application logic — the host surface has no editable
      prefill, see §5).
    - `undefined` (Escape) → **cancel**: the driver is never constructed, footer
      unchanged, no failure copy, no persisted credential.
  - **Headless mode:** the prompt never fires; the device-flow driver runs directly
    against `resolved`. Today a fresh `--headless` host blocks a non-interactive
    RFC 8628 flow on an interactive prompt (settled red-at-base by the Skeptic's
    probe); this is a named behavior change for §8's `/rc:login` row.
  - **Headless prints one line naming the resolved target** — the resolved URL must
    appear in headless output (settled-by-record design requirement, uncontested
    since round 2, recommended by Skeptic O8). Pinned in the test plan (T7).

## 4. Prompt copy (keyless, per the step-6 ruling)

The prompt is the consent moment. Its shape (design pass, converged rounds 2–3):

- **Bracket-default title:** `Control-plane server URL [<resolved>]:` — square
  brackets, not angle brackets (`<name>` is the substitution-token convention;
  bracket-default is a different, familiar convention). The resolved URL is
  embedded in the clause that names the server, not a trailing parenthetical.
- One **English consent sentence** naming the two actions (Enter to use the named
  server, type a different URL to override), replacing today's env-var
  parenthetical at index.ts:~566. The prompt text contains **no**
  `PI_REMOTE_SERVER_URL` / `piRemote.serverUrl` literals — those are internal
  plumbing.
- **The sentence ships keyless** — English under every locale — per `src/copy.ts`'s
  announced boundary and the binding step-6 ruling. Any future keying is its own
  boundary-expansion card carrying a *verified* Indonesian row.

The exact wording of the title and sentence is the design pass's call within the
acceptance substrings: it must contain the resolved URL, must make
Enter = enroll-against-this-URL readable (Enter is consent, not cancel), and must
not name env vars.

## 5. No editable prefill exists on the host surface — do not claim one

The installed SDK's `ExtensionUIContext.input` has no prefill capability
(`ExtensionUIDialogOptions` exposes only `signal`/`timeout`; `showExtensionInput`
forwards `{tui, timeout}`; `_placeholder` is inert; confirm resolves
`getValue()`, i.e. `""` on empty submit; cancel resolves `undefined`). "Pre-filled"
is therefore delivered as: the prompt **text** carries the resolved URL, and empty
submission is accepted as `resolved` by explicit application logic. This seam
verification is Skeptic O5, closed-green.

## 6. `noServerUrl` removal (Acceptance 4)

The resolver being total makes `login.failure.noServerUrl` unreachable. Remove all
artifacts:

- the `LoginReason` union member (src/login.ts:52);
- the `FAILURE_ROWS` row (src/login.ts:123–127);
- the driver-side defense-in-depth gate in `discoverForLogin`
  (src/login.ts:410–411);
- the command-layer check in `rcLoginCommand` (index.ts:615–617);
- the `rc.serverUrlRequired` footer row (src/login.ts:268) and id overlay row
  (src/copy.ts:73).

The closed-reason-set pin in `test/login.test.ts` shrinks by one. The removal is
**named in the PR description** (Phase-1 `error and empty-state text` ruling).

## 7. `readCredential` tightening (in-scope)

`readCredential` currently accepts any string `serverUrl`, including `""`
(src/credential.ts:224–238). This card deletes the guards (`rcCommand`'s
`!serverUrl`, the login-seam gate) that are the only things catching `""` today,
so the reader's laxness becomes load-bearing — the regression is introduced by
this card, not pre-existing debt.

- Empty/whitespace-only `serverUrl` → **corrupt → `null`** → the host surfaces as
  not enrolled. The predicate trims, matching the resolver.
- Named in the PR description as a deliberate tightening.

## 8. Footer `<serverUrl>` rendering (Acceptance 5)

Mechanism (dispute 3, converged): the **owner's refreshed closure cache**.

- A closure-scoped `resolvedServerUrl`, **initialized without a credential read**
  (`resolveServerUrl({ envUrl, settingUrl })`), refreshed at each of the three
  resolve sites (where the credential is already in hand), **before** any error
  render that path can produce.
- `applyFooter` (index.ts:213) substitutes
  `activeHttp?.serverUrl ?? resolvedServerUrl`.
- Non-error footer states ignore `serverUrl` and **stay that way** — the `off`
  footer remains exactly `"Off"` (en) / `"Mati"` (id), byte-equal, with no
  `<serverUrl>` token and no default URL substring (pin T5/R2-1). Showing the
  default in the `off` footer would claim an active dial target that doesn't
  exist.
- R2-1 is the binding test under this mechanism (designer R3; recorded preference
  for per-emission threading noted, not adopted).
