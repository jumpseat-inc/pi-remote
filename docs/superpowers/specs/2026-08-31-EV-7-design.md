# EV-7 Design Spec — `/rc:login` OAuth2 enrollment command

Card: `EV-7` (EPIC-1) — "`/rc:login` OAuth2 enrollment command"

Status: settled by Council deliberation (2 rounds, converged ≤ cap), Skeptic
attack (step-4; two closed-red blocks B1/B2 resolved in this draft, plus
open-untested implementation notices), consolidation, and product-owner
rulings **J1 / J2 / J3** (binding, applied in this draft — verbatim records in
`council/cards/EV-7.md` and `vault/raw/2026-08-31-po-ev7-ruling.md`). This
file is the **complete** design. If anything here is ambiguous, the design is
wrong — so it is not. The owner reads only this file (plus the files it
names). The owner's non-goal boundary is EV-8 (command registration,
`ctx.ui` rendering, `PI_REMOTE_SERVER_URL` read, the `authorizing` footer,
and the serverUrl env>stored>prompt resolution across `/rc` and `/rc:login`);
EV-7 builds and unit-tests the pure modules and syncs the §7.2 prose.

## 0. What the card is

Implement `src/login.ts` (pure OAuth2 flow drivers + a command facade) and
`src/credential.ts` (the credential store), and extend `src/tunnel.ts` with
an exported RFC 8414 `discoverAuthServer`. `/rc:login` provisions working
enrollment credentials for the configured control plane without env vars, in
an attended mode (browser present) and an unattended headless mode; `/rc`
thereafter creates tunnels with no further setup. EV-7 owns the pure modules
and their unit tests plus the §7.2 prose amendment. EV-8 wires the command
surface.

**Files touched by the PR:** `src/login.ts` (new), `src/credential.ts`
(new), `src/tunnel.ts` (discovery refactor — add exported
`discoverAuthServer`, change the `discoveryCache` type; no behavior change to
create/refresh/delete otherwise), `test/login.test.ts` (new) +
`test/credential.test.ts` (new) + additive tests in `test/tunnel.test.ts`
(dedicated discovery-failure test), `docs/PI-SPEC.md` (§7.2 credential-storage
prose sync + Windows caveat), `docs/superpowers/plans/2026-08-31-EV-7-implementation.md`
(new, the owner's plan). **Nothing else.** `src/index.ts` and `src/transport.ts`
are NOT touched (EV-8's wiring). The existing **85 tests stay green**.

## 1. The settled design (binding)

### 1.1 Module surface

All three modules are ctx-free / mutually deps-injected (fetch, now,
randomBytes, sha256, openUrl/browser shell-out, onState), matching the repo's
`createTransport` / `createState` DI style. No module-level mutable state.

**`src/credential.ts`** — the persistence owner. Serializes `piRemote.*`
keys to a dedicated credential file (see §1.3). Exports:

```ts
export interface EnrollmentCredential {
  serverUrl: string;
  accessToken: string;   // short TTL
  refreshToken?: string; // long-lived, revocable at the control plane
  tokenExpiry: number;   // absolute epoch-ms
  tenantId?: string;     // best-effort cached claim, never auth authority
}
export function credentialPath(deps: { configDir: string }): string;
export function saveCredential(cred: EnrollmentCredential, deps: { configDir: string; now?: () => number }): void;   // tmp+fsync+rename, mode 0600, atomic, full replace
export function saveCredentialAsync(cred: EnrollmentCredential, deps: { configDir: string; now?: () => number }): Promise<void>; // same, awaitable
export function readCredential(deps: { configDir: string }): EnrollmentCredential | null;   // null when absent/unreadable
export function clearCredential(deps: { configDir: string }): void;
```

- **Full replace on re-run, never merge** (ruling J2's atomicity reading of
  "replaces the previous credential cleanly"). Write-only-on-success: a
  failed flow writes nothing half-written.
- **Atomicity:** write to a temp file in the same directory, `fsync`, then
  `rename` over the target; on POSIX `fs.chmod(path, 0o600)` before rename.
- **J3 (binding):** on POSIX the file mode is 0600 (assertable via
  `fs.statSync(path).mode & 0o777 === 0o600`). On Windows `fs.chmod` is a
  no-op — EV-7 does **not** implement an NTFS ACL. The limitation is
  (a) documented in the README (rides FLLWUP-1) and (b) surfaced as a
  stateful notice in the storage-failed terminal copy when
  `process.platform === "win32"`. The storage-failed row carries the
  platform conditional in its render path.
- Return type for write: a `WriteResult { ok: true } | { ok: false; reason:
  "platform_acl_not_supported" | "io_error" }` so the login driver can append
  the Windows notice and render `login.failure.storageFailed`.

**`src/login.ts`** — the flow driver + copy vocabulary. Exports:

```ts
export type LoginMode = "attended" | "headless";
export type LoginReason =
  | "noServerUrl" | "unreachable" | "discoveryInvalid"
  | "browserOpenFailed" | "redirectTimeout" | "redirectMismatch"
  | "authorizationDenied" | "deviceDenied" | "tokenExchangeFailed"
  | "invalidTokenResponse" | "expiredCode" | "storageFailed" | "timedOut";
export type LoginOutcome =
  | { kind: "success"; tenantId?: string }
  | { kind: "cancelled" }
  | { kind: "failure"; reason: LoginReason };
export interface LoginReasonCopy { footerState: "error"; userLineKey: string; userLine: string; severity: "error"; }
export const loginReasonCopy: Record<LoginReason, LoginReasonCopy>; // §1.2 canonical 13-row failure set
export function loginEnglishFor(key: string): string;              // English-default lookup (closed set)
export const LOGIN_SUCCESS_COPY: string;                            // canonical success line (§1.2)
export const ALREADY_LOGGING_IN_COPY: string;
export const REPLACEMENT_PROMPT_COPY: string;
export interface LoginDeps { /* all injected: */ serverUrl:string; configDir:string;
  fetch: typeof fetch; now?: () => number; randomBytes?: (n:number)=>Uint8Array;
  sha256?: (input: Uint8Array)=>Promise<Uint8Array>;
  openUrl?: (url:string)=>Promise<boolean>;
  onState?: (s:string)=>void; /* emits "authorizing" when the flow begins */
  discoveryCache?: Map<string, Promise<DiscoveryDocument>>; }
export interface LoginCommand { run(mode: LoginMode, existing?: EnrollmentCredential | null): Promise<LoginOutcome>; cancel(): void; }
export function createLoginCommand(deps: LoginDeps): LoginCommand;  // EV-8 imports ONLY this facade
export const loginEndpointRequestLog: unknown[];                    // TEST seam: J2's assertable request log
```

Design notes:
- **Pure drivers + facade:** `runAttendedLogin(deps)` and
  `runHeadlessLogin(deps)` are pure, testable core drivers; the
  `createLoginCommand` facade wraps them with the single-in-flight guard and
  exposes `run(mode)` / `cancel()`. EV-8 imports only the facade
  (`createLoginCommand`), plus `loginEnglishFor` / `LOGIN_SUCCESS_COPY` for
  rendering. EV-8 never calls the raw drivers.
- **Single-in-flight guard:** a `cancel()` token / in-progress flag per
  command instance; a second `run` while one is in flight returns a
  `{ kind: "failure", reason: "alreadyRunning" }`? **No** — `alreadyRunning`
  is surfaced by EV-8 via `ALREADY_LOGGING_IN_COPY`; the facade exposes the
  in-flight state and EV-8 renders the line. The facade does not render.
- **J2 (binding), replacement prompt lives in the driver:** inside
  `run(mode)`, when an existing credential is present **and** `mode ===
  "attended"`, render `login.replacementPrompt` via `loginEnglishFor` and
  wait for Enter **before any HTTP request** to `authorization_endpoint`,
  `token_endpoint`, or `device_authorization_endpoint`. Ctrl-C aborts
  silently (existing credential preserved, clean exit, nothing emitted). In
  **headless** mode the prompt is **not** shown (J2 micro-decision; the
  driver branches on mode, EV-8 does not). The gate is asserted by
  pre-seeding the credential store and inspecting the request log: the
  request log shows no endpoint request until the prompt is confirmed
  (§2 test 10).
- **J1 (binding), tenant display:** the success line appends
  ` (tenant <tenantId>)` **only when** `typeof tenantId === "string" &&
  tenantId.length > 0` (the best-effort base64url decode of the access-token
  JWT payload `sub` returned a non-empty string). Otherwise render the
  compact form verbatim. Implementation note: `tenantId` is an unverified
  best-effort decode and the display is **informational only** — it
  authorizes no tenant-scoped behavior at the host.
- **Cancellation (J2 Ctrl-C, plus general SIGINT):** Ctrl-C during any live
  flow renders `login.cancelled` and issues **zero** additional POSTs to any
  endpoint after the signal (assertable via the request log).
- **Never throws across its public surface:** `run(mode)` returns a
  `LoginOutcome`; all failure paths are typed `LoginReason`s, never raw
  exceptions or raw HTTP bodies.
- **Determinism:** injected `now`, `randomBytes`, `sha256`; no module-level
  `Date.now` / `crypto` / `Math.random`.

**`src/tunnel.ts` extension (B1 resolution — binding):** export
`discoverAuthServer`, and change the shared discovery cache type:

```ts
export interface DiscoveryDocument {
  authorizationEndpoint: string;
  tokenEndpoint: string;
  deviceAuthorizationEndpoint?: string; // optional per RFC 8414/8628
}
export function discoverAuthServer(deps: TunnelHttpDeps): Promise<DiscoveryDocument>;
```

- **Cache type (B1):** change `TunnelHttpDeps.discoveryCache` from
  `Map<string, Promise<string>>` to `Map<string, Promise<DiscoveryDocument>>`
  (choice (a) — single cache, not a second one). This is a mechanical type
  widening; existing tests inject `new Map()` and remain assignable (tsc
  green) and runtime-identical.
- **Validation:** a discovered doc is valid iff `authorizationEndpoint` and
  `tokenEndpoint` are non-empty strings. `deviceAuthorizationEndpoint` is
  optional; a valid doc may omit it.
- **Eviction:** on rejection, evict the cached entry (the existing
  catch-and-delete behavior is preserved for the cache).
- **Behavior preservation (Skeptic-verified constraint):** in `tunnel.ts`,
  discovery failure still maps to `TunnelReason "control_plane_unreachable"`
  — `TunnelReason` does **not** gain a member. `refreshAccessToken` calls
  `discoverAuthServer` and reads `.tokenEndpoint`; only when
  `tokenEndpoint` is missing does refresh throw `control_plane_unreachable`.
  The closed-set test at test/tunnel.test.ts:357-363 stays green.
- **`discovery_invalid` is login-only:** `login.ts` maps a non-valid doc
  (missing `authorization_endpoint`/`token_endpoint`) and — in headless
  mode — a missing `deviceAuthorizationEndpoint` to its own
  `LoginReason "discoveryInvalid"`. This distinguishes "missing optional
  field" from "discovery unreachable" (Skeptic step-4).

**Invariant (enforceable, B2-correct):** the closed-set test asserts
`Object.keys(loginReasonCopy).sort()` equals exactly the closed 13-row
failure set (no new member, no drop), and that **every row's `userLine`
contains at least one** of the marker fragments `no credentials were saved`,
`run /rc:login`, or `control-plane admin` (for `unreachable`, the sole
exception, the row's per-row tail `check your network and try again.` is
asserted instead — the invariant is pinned per-row, not as a uniform
regex). Each row's English string is additionally pinned verbatim in this
table's "English default" column and asserted exactly by the owner's tests.

**Distinctness assertions (Skeptic gate), all unit-tested:**
- `login.attended.success` and `login.headless.success` resolve to the
  **same** English string (only the key differs by mode).
- `login.failure.authorizationDenied` and `login.failure.deviceDenied`
  resolve to **distinct** strings.
- `login.failure.redirectTimeout`, `login.failure.expiredCode`, and
  `login.failure.timedOut` resolve to **three distinct** strings.
- `login.failure.unreachable` and `login.failure.discoveryInvalid` are
  **distinct**.

**Voice rules (binding):** sentence case, em-dash cadence, second-person
imperative, backticks for commands and user-relayable values, angle brackets
for caller-filled placeholders. No `wss://`, no `device_code`, no
`access_token`, no `refresh_token`, no HTTP body, no stack trace, in **any**
user-visible string. `process.env` never appears in `login.ts` (the env
override reads `PI_REMOTE_SERVER_URL` upstream in EV-8). Static guards
enforce this (G-3 below). `<serverUrl>` is the configured control-plane URL,
never the one-time tunnel URL.

### 1.3 Persistence (J3 + §7.2 amendment — binding)

pi exposes **no** generic extension-settings write API and no chmod-0600
guarantee on its settings.json (verified in EV-7 step-2 by owner and
principal independently: `appendEntry` is session-scoped;
`SettingsManager.Settings` has a closed shape with no arbitrary-key setter).
EV-7 therefore ships a **dedicated credential store**: a single JSON file at
`<configDir>/pi-remote/credentials.json` (plural; B2's filename pin),
mode 0600 on POSIX, serializing the `piRemote.*` keys
(`serverUrl`, `accessToken`, `refreshToken?`, `tokenExpiry`, `tenantId?`).
The `piRemote.*` keys are the contract EV-8 consumes; the backing file is
EV-7's choice. Atomic tmp+fsync+rename; written only on success; re-run =
full replace.

**§7.2 prose amendment (same PR, evidence-cited per EV-1 Q3 / EV-4 Q1
governance):** amend docs/PI-SPEC.md §7.2 "Credential storage" (and the §8
`/rc:login` row's "Persists the credential in extension settings" phrase) to
name the dedicated 0600 credential file instead of "extension settings",
adding the user-only-readability platform mechanism note and the J3 Windows
caveat (documented in the README's credential-storage section, riding
FLLWUP-1, plus the stateful notice in the storage-failed copy on
`process.platform === "win32"`). No other §7.2 mechanics change.

### 1.4 Flows

**Attended (`/rc:login`, default):** resolve `serverUrl` (env>stored>prompt
is EV-8's job; EV-7 receives the resolved value). If an existing credential
is present, render `login.replacementPrompt` and wait for Enter (headless
exempt) **before** any HTTP. Render `login.attended.opening`, then always
`login.attended.fallback` (the URL is printed even when auto-open succeeds —
it is the recovery). Attempt `deps.openUrl(authorizeUrl)` (best-effort,
swallowed; failure does not abort). Render `login.attended.waiting`. Bind a
loopback listener on `127.0.0.1` ephemeral port 0 **before** building the
authorize URL; serve only `GET /callback` (state-checked; open-redirect
guard); the listener lives only for the command and closes in `finally`. On
callback: exchange `authorization_code` + `code_verifier`
(`grant_type=authorization_code`, public client, **form-urlencoded**, no
client secret) at `token_endpoint`. On 200: parse, `saveCredential`
atomically, render `login.attended.success` (J1 tenant parenthetical
conditional), exit 0. On `redirectMismatch` / `redirectTimeout` /
`tokenExchangeFailed` / `invalidTokenResponse` / `authorizationDenied` /
`unreachable` / `discoveryInvalid` / `storageFailed`: render the matching
failure row, exit non-zero.

**Headless (`/rc:login --headless`):** no replacement prompt (J2). Render the
four-line relay block (`login.headless.instructions`, `.carry`,
`.code`, `.codeValue`) then `login.headless.expire` — the bearer value is
`verification_uri_complete` by default, bare `verification_uri` only as a
fallback. POST `device_authorization_endpoint` (required for headless) →
`{device_code, user_code, verification_uri, verification_uri_complete,
expires_in, interval}`. Poll `token_endpoint` with
`grant_type=urn:ietf:params:oauth:grant-type:device_code`, honoring
`interval` and `slow_down` (+5s). Silent between polls; ≤3 bound progress
prints (`login.headless.half` at expires_in/2, `.thirty` at expires_in−30s,
and — if applicable — the `expired_token` tail). **Never re-print
`user_code`.** Terminal RFC 8628 errors → `authorizationDenied` /
`deviceDenied` / `expiredCode`; transport/validation → `unreachable` /
`discoveryInvalid` (incl. missing `deviceAuthorizationEndpoint`) /
`tokenExchangeFailed` / `invalidTokenResponse`. On 200: persist atomically,
render `login.headless.success`, exit 0.

**Cancellation:** SIGINT renders `login.cancelled` exactly once and issues
zero POSTs after the signal. Flow-internal total timeout →
`login.failure.timedOut` (distinct from `redirectTimeout` / `expiredCode`).

### 1.5 EV-8 seam (binding, per ruling)

EV-7 exports `createLoginCommand`, `LoginOutcome`, `LoginReason`,
`loginReasonCopy`, `loginEnglishFor`, `LOGIN_SUCCESS_COPY`,
`ALREADY_LOGGING_IN_COPY`, `REPLACEMENT_PROMPT_COPY`, and the store functions
(`readCredential` / `saveCredentialAsync` / `clearCredential`). EV-8 imports
**only** the facade + the lookup + store functions; it never calls the raw
drivers and never duplicates the strings (general rule, binding). The join
test (§2) demonstrates the acceptance "a following `/rc` creates a tunnel":
`run → readCredential → createTunnel` against a fake control plane, zero env.

    `GET /callback` on 127.0.0.1 with a matching `state`; mismatched

15. **Atomicity / crash-safety:** a failed write leaves no half-written

## 4. Acceptance mapping (the card's `goal`)

- **Attended:** browser flow completes with ≤ command + browser interaction;
  a following `/rc` creates a tunnel — §1.4 attended + test 16.
- **Headless:** relays a single short value (`verification_uri_complete` +
  `user_code`); terminal copy states exactly what to carry where — §1.4
  headless.
- **Survives restart:** credential persisted (§1.3); `/rc` uses it without
  prompting — `readCredential` + join test 16.
- **Failed/cancelled leaves no half-written credential + says so:** §1.3
  atomicity + typed failure rows (test 15).
- **User-only readability + clean re-run replace:** POSIX 0600 (J3 gate,
  test 13) + Windows caveat §1.3; full-replace re-run + replacement prompt
  (J2, tests 10–11).
