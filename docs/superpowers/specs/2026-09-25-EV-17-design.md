# EV-17 — Let the user cancel an attended `/rc:login` — design spec

Card: `council/cards/EV-17.md` (EPIC-7). Execution mode `Deliberate`; surface-touching.
Basis: the card's settled `## Shared design pass` block, the step-2–5 deliberation record
(`council/cards/EV-17-deliberation/`), and the three binding step-6 product-owner rulings
(job-22, recorded on the card face). Nothing here reopens what those closed.

## Goal (verbatim from the card)

During an attended `/rc:login`, the user can take an in-session cancel action that ends the
command before the 300-second `redirectTimeoutMs` elapses, yielding
`LoginOutcome { kind: "cancelled" }`, printing exactly
`Sign-in cancelled — no credentials were saved.` once, and saving no credential.

## Settled design

### 1. Type remediation (ruling Q1 — route (a))

Extend the vendored `src/pi-sdk-on.ts` `PiExtensionContext.ui` object to declare `confirm`
with the full real installed signature:

```ts
/** Real signature (installed types.d.ts:73; ExtensionUIDialogOptions :37-42):
 * confirm(title: string, message: string, opts?: { signal?: AbortSignal; timeout?: number }): Promise<boolean> */
confirm(title: string, message: string, opts?: { signal?: AbortSignal; timeout?: number }): Promise<boolean>;
```

Both optional members are declared — `signal?: AbortSignal` (types.d.ts:39) and
`timeout?: number` (types.d.ts:41) — per the EPIC-6/FLLWUP-39 declare rule: declare, do
not omit. This is the only route (rejected: real-SDK dependency — contradicts R-TYPE-1
"the SDK is not a dependency; the vendored mirrors are the boundary"; cast-based escape —
violates the vendored bridge's cast-free discipline and R-PAYLOAD-1's correct-not-annotate
default). `src/pi-sdk-on.ts` is a named changed file of this card.

### 2. Affordance and dependency wiring

- New optional member on `LoginDeps` (`src/login.ts`):
  `waitForCancel?: (signal: AbortSignal) => Promise<boolean>`.
- New optional members on `RemoteControllerDeps` (`index.ts`), implemented in the
  `export default` closure where `requireCtx` is lexically in scope (the O-1-closed
  scope fact: `requireCtx` does not resolve at the `createLoginCommand` call site,
  TS2552):
  - `uiConfirm?: (title: string, message: string, opts: { signal?: AbortSignal }) => Promise<boolean>`
    — implemented as `(title, message, opts) => requireCtx().ui.confirm(title, message, opts)`
    (lazy capture, the same pattern as `inputPrompt` at `index.ts:950`).
  - `hostMode?: () => string` — implemented as `() => requireCtx().mode`
    (`PiExtensionContext.mode`, vendored at `src/pi-sdk-on.ts:35`, real provenance
    ExtensionContext `mode: "tui" | "rpc" | "json" | "print"`).
- Threading at the `createLoginCommand({...})` call site inside `rcLoginCommand`
  (~`index.ts:676`), evaluated at command-run time (the command handler has already set
  `ctxHolder`, so `requireCtx()` is valid there):

  ```ts
  waitForCancel:
    deps.uiConfirm && deps.hostMode() === "tui"
      ? (signal) => deps.uiConfirm(TITLE, MESSAGE, { signal })
      : undefined,
  ```

  with `TITLE`/`MESSAGE` the verbatim constants from §4.

### 3. Non-interactive host gating (ruling Q2 — gate)

`waitForCancel` is wired **only** where `confirm` can genuinely wait on a user: the gate
keys on the real, verifiable host property `ctx.mode === "tui"` (the only run mode whose
`confirm` parks on a live user; per the ruling's grounding, RPC `confirm` resolves
`false` immediately, which under the settled re-arm semantics would be a live re-arm spin
for the full `redirectTimeoutMs`). The gate changes **presence, not behavior** — where
wired, semantics are exactly the settled ones (re-arm on `false` until the signal aborts).
In all other modes the dep stays `undefined`: no affordance is offered and the attended
wait ends by callback, mismatch, or timeout exactly as at base.

### 4. Copy — byte-exact, unchanged (settled block, not re-litigable)

- Wait line: `login.attended.waiting` = `Waiting for browser…` — unchanged.
- Dialog title: `Waiting for browser…`; dialog message: `Cancel sign-in?`.
- Cancel line: `login.cancelled` = `Sign-in cancelled — no credentials were saved.`
  (byte-exact at `src/login.ts:201`), printed **exactly once by the facade, never by the
  driver**.
- The two new strings (dialog title, dialog message) are pinned as exported verbatim
  constants in `src/login.ts` (Stable Keys precedent). No `src/copy.ts` keyed rows; one
  coverage-boundary sentence only.
- No new refusal line; no `/rc:login:cancel` command (rejected on evidence: a command
  typed mid-wait cannot dispatch — the host's input loop is parked in `session.prompt`).

### 5. Driver mechanism (`src/login.ts` `runAttendedLogin`)

All abort plumbing is new (O-4: zero `AbortController`/`abort()`/`AbortSignal` matches in
`src/*.ts` + `index.ts` at base):

- **Single guarded finisher.** One `finish(result)` — `if (settled) return; settled =
  true; clearTimeout(timer); ctrl.abort(); settle(result);` — routed from **all four**
  terminal paths: server callback win, timer fire, confirm-cancel (dialog resolved
  `true`), and external `cancel()` via `wake`. First-wins is total; the callback winning
  aborts the signal to dismiss the dialog; the timer is cleared to prevent a duplicate
  timeout settle. The existing post-await `clearTimeout` stays as defense.
- **Driver-side re-arm loop** over `waitForCancel`, condition written explicitly as
  `while (!signal.aborted && !settled)` (spin-proof even if a future settle path forgets
  to abort). **Rejection re-arms** (rejection ≠ abort ≠ cancel; Escape-keeps-waiting
  semantics), with an explicit test. The loop checks `signal.aborted` after each await,
  never branches on the resolved value to detect abort (O-2: abort is an ordinary
  `false` in both TUI and RPC hosts, never a rejection; TUI polarity is affirming
  `["Yes","No"]` with `=== "Yes"`, so `true → cancelled` holds).
- **Confirm-cancel settles `{ type: "cancelled" }` without setting `ctl.cancelled`** —
  the currently-dead `cb.type === "cancelled"` branch (`src/login.ts:~575`) becomes
  reachable via two honest causes (server-cancelled callback; user confirm-cancel).
- **External `cancel()`** (`createLoginCommand.cancel()`, `index.ts:~912`): sets
  `ctl.cancelled = true` (unchanged), then wakes — `wake` is `finish({ type:
  "cancelled" })` — so the wait is actually woken and the dialog dismissed, not just a
  flag flipped. No production caller of `cancel()` exists (verified by grep); Acceptance
  5's "wired to the surface" is satisfied by the confirm dialog alone, and `cancel()`'s
  wake is documented as a test/external seam, explicitly not a second user surface.

## Test map (Acceptance → tests)

Existing suite stays green unmodified (`bunx tsc --noEmit` clean; `bun test` 320 pass /
1 skip / 0 fail at base).

1. **A1 — named affordance, exact copy, no endpoint traffic after cancel** (`test/login.test.ts`,
   raw-driver harness): drive `runAttendedLogin` with a `waitForCancel` gate resolving
   `true`; assert outcome `{ kind: "cancelled" }`, exactly one occurrence of the literal
   cancel line, and zero token-endpoint or device-endpoint requests after the signal.
2. **A1 print-once is asserted through the facade, never the raw driver** (the print
   lives in the facade; a raw-driver assertion is vacuously green with zero prints):
   `createLoginCommand({..., waitForCancel: gate}).run("attended")` counting the literal
   line.
3. **A2 — discriminating timing**: measured elapsed wall-clock strictly less than the
   injected `redirectTimeoutMs` (interrupt ≠ reason-flip at timer fire).
4. **A3 — cancel path, not timeout path**: small injected `redirectTimeoutMs` (e.g.
   2000 ms, gate at ~10 ms).
5. **A4 — no credential file written or modified.**
6. **A5 — dead-branch reachability, per Skeptic O-5's settling test**: drive
   `runAttendedLogin(deps, null, ctl)` with a **test-owned** `ctl`, gate resolving
   `true`; assert `outcome.kind === "cancelled"` **and** `ctl.cancelled === false` — an
   implementation that sets the flag on the confirm path fails, proving the callback
   branch (not the flag branch) executed.
7. **Red-at-base record (O-3-corrected, timing-only)**: at base, mid-wait
   `ctl.cancelled = true` does **not** wake the wait — measured elapsed ≥
   `redirectTimeoutMs`, and the base outcome is `{ kind: "cancelled" }` (the flag check
   precedes the timeout branch). The record cites O-3's probe, **not** the fabricated
   `vault/wiki/login.ts.md:55` citation (that page is 25 lines; the citation is struck
   from the record). A red test written against "reason `redirectTimeout`" would
   mis-diagnose and is not written. The print-once assertion is green at base too and
   does not discriminate.
8. **Rejection re-arms**: fake `waitForCancel` rejects once then resolves `true` ⇒
   outcome `cancelled`, dep invoked twice.
9. **Finisher totality**: server-callback win, timer fire, confirm-true, and `cancel()`
   each observe exactly one settle, one abort, one `clearTimeout`; no re-arm after a
   legitimate win (dep call count stops increasing after the win; `signal.aborted ===
   true` at settle).
10. **No spin on abort**: `waitForCancel` resolving `false` on abort; drive abort via
    `cancel()`; loop invocation count stops; run resolves `{ kind: "cancelled" }`.
11. **Non-interactive gate (Q2)**: with the host mode anything other than `"tui"`
    (and/or `uiConfirm` absent), `waitForCancel` is `undefined` — no affordance, wait
    ends by timeout exactly as at base.
