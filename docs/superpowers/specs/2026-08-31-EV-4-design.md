## 1. The settled design (binding)

### 1.1 The mapper is a pure fold

```
translate(input: PiEvent | JsonlEntry, state: TranslateState): { frames: AgUiFrame[]; state: TranslateState }
```

- Pure function: **no I/O, no socket/session references, no hidden closure, no `crypto.randomUUID`, no `Date.now`, no `Math.random`**. The type signature and a lint/grep guard prove this. `input` in, `frames` + next `state` out.
- `translate.ts` is a module with **no side effects on import**. It may import type definitions only. It must not import socket, session-manager, transport, logger, or clock modules (the same guard EV-5 relies on to import it unchanged).
- `input` covers a pi event (live path) or a normalized JSONL entry (replay path). The accepted shapes and the per-row mapping are defined in §2.

`TranslateState` carries only primitive deterministic fields needed to thread framing across calls:

- `sessionId: string` — the source of `threadId` (a plain string; **not** a session-manager or socket object).
- `runId: string` — **input-driven, never minted by translate**. Live path passes a fresh UUID per `agent_start`/`agent_settled` cycle; replay path (EV-5) passes a deterministic `runId` per past run. translate consumes it and emits it on `RUN_STARTED`/`RUN_FINISHED`.
- `openMessages: Map<string, OpenMessageState>` — the fold bookkeeping that lets START/END framing close correctly (an open assistant message, an open thinking pane, an open tool call).
- `eventOrdinal: number` — a monotonic counter for deterministic inner correlation derivation (replay determinism); advance on each frame produced.

`threadId` on `RUN_*` = `state.sessionId`. `stepName` on `STEP_*` is the constant `"turn"`. The dedupe/`seq` envelope id **does not belong to translate** — it is EV-3 transport turf (§6 envelope); translate emits bare AG-UI frames only.

### 1.2 Correlation ids (all deterministic in replay, distinct in live)

| Field | Source |
|---|---|
| `threadId` | `state.sessionId` (plain string) |
| `runId` | input (`state.runId`), never minted here |
| assistant `messageId` | live: minted per message; replay: `"msg-<entryId>"` |
| thinking `messageId` | `"<assistantId>:think:<contentIndex>"` (per content block) — both paths |
| `toolCallId` | pi's tool call id (`toolcall_start.id` / `toolCall.id`), stable live+replay |
| `stepName` | constant `"turn"` (JSONL has no turn/run entries; see S9) |
| tool-result `messageId` | the toolResult message's id, in assistant source order |

### 1.3 CUSTOM event shape (converged, binding)

The **only** escape hatch. No second wire format ever:

```
{ type: "CUSTOM", name: "pi.<category>", value: { pi: <raw pi event name>, data: <semantic payload> } }
```

- `name` is the **sole dispatch key** — `pi.human_input`, `pi.context.*`, `pi.session.*`, `pi.tool.*`.
- `value.pi` is pi provenance (the raw event name, e.g. `"ui.confirm"`), not a second switch.
- `value.data` is the semantic payload.
- `pi.human_input` approval: `value = { pi: "ui.confirm", data: { promptKind, prompt, schemaVersion: 1, promptId: <deterministic hash> } }` — `schemaVersion` and a deterministic `promptId` so EV-6 resolves human input once across replay.

### 1.4 Replay contract (ruling Q2, binding)

- Replay emits **one `RUN_STARTED` / `RUN_FINISHED` pair per past run**, mirroring live. `translate.ts` never mints run ids; EV-5 threads a deterministic `runId` per past run through `TranslateContext`/`state` for that past run's frames.
- EV-4 publishes the contract: **`runId` is input-driven**. The past-run-boundary derivation rule is EV-5's to publish (a user entry through the last assistant or toolResult message before the next user entry) — the same shape as turn derivation.
- Inner correlation ids (§1.2) and CUSTOM `promptId` are deterministic so replay twice of the same JSONL produces byte-identical frames with identical ids.

## 2. The §4 row-by-row mapping (the contract translate.ts implements)

One representative pi event per row → exact AG-UI frames. Rows marked **[Q1-corrected]** replace the literal §4 rows the Skeptic closed-red (S1/S2/S8); the corrected rows are what the owner implements, and what the §4 amendment (see §4) writes into the spec.

| pi surface | AG-UI frame(s) | Notes |
|---|---|---|
| `agent_start` | `RUN_STARTED { type, threadId, runId }` | threadId = sessionId; runId from state |
| `agent_settled` | `RUN_FINISHED { type, threadId, runId }` | `agent_settled`, **never `agent_end`** (retries/compaction retries must not emit premature run-end); **no `RUN_ERROR` row** (Q1/designer) |
| `message_update` assistant text deltas | `TEXT_MESSAGE_START { messageId, role:"assistant" }` → `TEXT_MESSAGE_CONTENT { messageId, delta }` → `TEXT_MESSAGE_END { messageId }` | streamed assistant reply; START on first text delta, END when message closes |
| thinking content in `message_update` **[Q1-corrected]** | `REASONING_MESSAGE_START { messageId, role }` → `REASONING_MESSAGE_CONTENT { messageId, delta }` → `REASONING_MESSAGE_END { messageId }` | **not** `THINKING_TEXT_MESSAGE_*` (S1: deprecated → `REASONING_MESSAGE_*`); messageId `<assistantId>:think:<contentIndex>`; split mixed text+thinking by content-block type |
| tool call **generation lane** `message_update.assistantMessageEvent` `toolcall_start`/`toolcall_delta`/`toolcall_end` **[Q1-corrected]** | `TOOL_CALL_START { toolCallId, toolCallName, parentMessageId }` → `TOOL_CALL_ARGS { toolCallId, delta }` → `TOOL_CALL_END { toolCallId }` | S2: generation lane carries args and preserves source order; `toolCallId` = pi call id; `parentMessageId` = requesting assistant messageId (threaded via fold state, seeded at `toolcall_start`) |
| `tool_execution_start`/`_update`/`_end` **[Q1-corrected]** | `CUSTOM` `pi.tool.*` | S2: fires in a separate execution lane **after** `message_end` (false temporal order for `TOOL_CALL_*`); `tool_execution_update` carries static args + `partialResult` (output, not an args delta) — output is not in AG-UI's tool-progress vocabulary, so no smuggled `TOOL_CALL_ARGS` |
| `tool_result` **message** events | `TOOL_CALL_RESULT { messageId, toolCallId, content, role:"tool" }` | final result in assistant source order; keyed off the toolResult **message**, never `tool_execution_end`; **content flattened to `string` (S8)** from `(TextContent\|ImageContent)[]` — concatenate text, represent/skip images |
| `turn_start` / `turn_end` | `STEP_STARTED { stepName:"turn" }` / `STEP_FINISHED { stepName:"turn" }` | `stepName` constant; JSONL has no turn/run entries (S9) |
| `ui.confirm` / approval (`ui_prompt_start`/`ui_prompt_end`) | `CUSTOM` `pi.human_input` | value `{pi:"ui.confirm", data:{promptKind, prompt, schemaVersion:1, promptId}}` |
| `context` / token budgets / compaction (`session_compact`) | `CUSTOM` `pi.context.*` | escape hatch |
| `model_select`, `thinking_level_select`, `session_info_changed` | `CUSTOM` `pi.session.*` | client-side status |
| user input (from a client) | `TEXT_MESSAGE_START { role:"user" }` → `TEXT_MESSAGE_CONTENT` → `TEXT_MESSAGE_END` | injected locally, then echoed like any other message |

**Mapping discipline:**
- Thinking and text within one `message_update` are **split by content-block type** into their respective frame families (a `think,think,text` stream → `REASONING_START/2×CONTENT/END` then `TEXT_START/CONTENT/END`).
- `TOOL_CALL_ARGS.delta` is `JSON.stringify(args)` — **never** `partialResult` (S6: `delta` is a JSON-string-typed field; serializing output instead of args silently corrupts the tool UI).
- A single `TOOL_CALL_ARGS` snapshot between START and END is AG-UI-valid (S11); live may stream multiple deltas, replay emits one snapshot.
- The tool **generation lane** (`toolcall_delta`) may be richer live than replay (replay has only the full `ToolCallContent.input` snapshot); the mapper accepts both — one snapshot minimum.

## 3. Fixture / test contract (what the acceptance means)

A fixture suite lives under `test/`, feeds **one representative pi event per §4 row** (§2 table), and asserts the **exact AG-UI frames** emitted, including START/END framing around streamed messages and `agent_settled` (not `agent_end`) driving `RUN_FINISHED`. At minimum it must assert, per the settleable claims and open objections:

- O1 (S1 green): thinking content emits `REASONING_MESSAGE_*`, never `THINKING_TEXT_MESSAGE_*`; `frame.type` equals the AG-UI enum literal.
- O2 (S2 green): `toolcall_start/delta/end` → `TOOL_CALL_START/ARGS/END`; `tool_execution_update{args,partialResult}` → **no** `TOOL_CALL_*`, only `CUSTOM pi.tool.*`; `TOOL_CALL_START.parentMessageId` === the requesting assistant messageId.
- O3 (S8 green): `TOOL_CALL_RESULT.content` is a flat `string` (blocks concatenated/flattened), never an object array.
- CUSTOM every frame: `frame.type === "CUSTOM"`, `name` starts `pi.` and is the sole dispatch key, `value` has keys `pi` and `data`.
- Replay determinism: translating the same entry sequence twice yields byte-identical frames and identical correlation ids (incl. inner ids).
- `runId` input-driven: translate never mints a run id itself; threading a provided `runId`/`sessionId` produces the expected `RUN_*` frames; consuming a per-run runId emits one `RUN_STARTED`/`RUN_FINISHED` pair per run.
- Every `STEP_STARTED`/`STEP_FINISHED` has `stepName === "turn"`.
- Static guard: grep/import test that `translate.ts` contains no `crypto.randomUUID`, `Date.now`, `Math.random`, and no socket/session/transport imports; importing the module has no side effects.

## 6. Explicit non-goals (from the deliberation record)

- **No `RUN_ERROR` row** — EV-4 does not add one (Q1/designer); `agent_end`-without-`agent_settled` is deferred to the principal seat for EV-8's contract, **not** handled here.
- **No envelope id / `seq` / `ack` / dedupe id** — that is EV-3 transport turf (§6), not translate's.
- **No `MESSAGES_SNAPSHOT`** — compaction's full snapshot shape is EV-5 territory; EV-4 only maps `session_compact` → `CUSTOM pi.context.*`.
- **No import normalization, no history reading, no runId derivation** — EV-5's job; translate consumes input and a threaded runId.
- **No `partialResult` smuggling into `TOOL_CALL_ARGS`** (S2/S6) — execution-lane output is `CUSTOM pi.tool.*` or dropped (acceptance requires no tool-progress frame; live tool-progress later would be a `CUSTOM pi.tool.progress` follow-up, not EV-4).
- **No new runtime npm dependencies** required; type definitions for AG-UI frames may be declared locally (the repo has no AG-UI SDK dependency). The typecheck gate must stay green.
- **No changes to §5, §6, §7, §8 of PI-SPEC** beyond the §4 amendment in §4 above.
