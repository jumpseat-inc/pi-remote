# EV-19 Design — Verify the /rc:login URL placeholder renders at the installed-host boundary

Card: `council/cards/EV-19.md` (EPIC-8). This spec records what the Council
deliberation settled (rounds 1–2 plus the Skeptic's step-4 attack); it
derives nothing new. The owner implements exactly this.

## 1. What this card is

An **observational** card with **zero product diff**: the branch this card
produces must touch no `src/**` and no `index.ts` (`git diff
origin/main...HEAD --stat` shows only record artifacts, the observation
record, the mock script, and the plan). EV-18 (merged, PR #54) already
forwards the resolved control-plane URL as `ui.input`'s second
(`placeholder`) argument; this card observes at the installed pi 0.87.1
host what that argument actually renders, records the anticipated negative
(the placeholder does NOT render greyed), and discharges acceptance (c) via
a local mock control plane. The anticipated non-render is the card's
honest success, not a failure.

Binding rulings applied (cite in the record):
- Phase-1 "surface copy": the attended `/rc:login` prompt title stays
  byte-unchanged; EV-19 mints no copy.
- Phase-1 "error and empty-state text": empty submission enrolls against
  exactly the resolved URL; typed input overrides; Escape cancels.
- Phase-1 "state and field naming": the second `ui.input` parameter is
  named `placeholder`; nothing else is renamed.
- Product-owner scoping note (acceptance (c)): discharged by pointing the
  prompt at a **local mock control plane**, pressing empty-Enter at the
  real host prompt, and byte-comparing the persisted credential
  `serverUrl` to the resolved URL. If that mock path genuinely cannot be
  produced unattended, record the gap as a deviation under acceptance (d).
  A recorded deviation is the card's honest output; a manufactured claim
  is not.

## 4. Observation (a)+(b) — the render, with the corrected P1 method

Run the orchestrator's proven tmux path in the owner worktree: fresh
`PI_CODING_AGENT_DIR` (tmp dir), `OPENROUTER_API_KEY` set,
`pi --no-session --extension <worktree>/index.ts`; accept the trust
prompt; type `/rc:login` + Enter; capture the pane.

Capture modes (both, named in the record with what each can show):
- **Primary: `tmux capture-pane -e -p -J`** (SGR preserved). The negative
  observation and any style claim are only checkable on these bytes. (The
  Skeptic settled the premise live: `-p` strips SGR to zero `033` bytes;
  `-e` preserves `\x1b[2m`/`\x1b[38;5;…m`.)
- **Companion: `tmux capture-pane -p -J`** for human-readable grep, title
  substring checks, and authorize-URL parsing.

Timing: capture after the prompt has fully rendered and before any
keystroke (P4); confirm no transient spinner/loading frame above the
title.

**The signed negative (P1, corrected per the Skeptic's closed-red on the
as-stated method — adopt these three corrections verbatim):**
- **Span:** the input-line span is the line beginning with the `>` prompt
  marker and carrying the host's CURSOR_MARKER (`\x1b_pi:c\x07`) — NOT
  "the last non-blank line" (the component adds the input, then a spacer,
  a dim key-hint row, another spacer, and the bottom `DynamicBorder`; the
  last non-blank line is the border).
- **Expected-present:** the span contains exactly one SGR sequence — the
  `\x1b[7m … \x1b[27m` inverse-video cursor space. The signed negative
  states this as expected-present; a bare "no SGR in the span" is
  spurious.
- **Search set:** assert absence of any style SGR inside the span other
  than that cursor sequence — not a dim-only search. A dim-only search is
  blind to this host's own placeholder mechanism, which renders
  reverse-video (`\x1b[7m`-wrapped), not dim (`input.js:349-358`, default
  `placeholderStyle` identity).

**Title fallback (P2):** the bracket form `[<resolved>]` and the consent
sentence `Press Enter to enroll this host against <resolved>, or type a
different URL to override:` appear in the capture, asserted on the
SGR-stripped projection (the `-p` companion, or the ANSI-stripped text of
the `-e` capture) — never raw-`-e`-vs-source (SGR interleaving would fail
spuriously). Compare against the keyless inline literal at
`index.ts:676-678`; `src/copy.ts` documents the literal as keyless.

**`login.urlPrompt` honesty:** the consent sentence is a keyless inline
literal; `grep -rn 'login.urlPrompt' src/` returns zero hits (settled,
closed-green). The record cites the literal by exact string plus the
capture's SHA-256, never as a landed key, and carries one sentence noting
that the Phase-1/PO prose's `login.urlPrompt` key name has no tree
referent (keying it is FLLWUP-41, still Backlog).

No backspace-to-empty or clear-on-type dynamics are exercised: nothing
renders in the box on pi 0.87.1, so that conditional acceptance branch
stays unexercised and is recorded as such (P6 — future honoring host — is
hypothesized-only, out of scope).

## 5. Enrollment (c) — the local mock control plane

Binding facts (Skeptic-settled, closed-green): production never binds
`openUrl` (`index.ts:121` declared, `:700` passed through, nothing binds
it), so the attended driver prints the **full authorize URL** through the
notify sink (`login.attended.fallback`, `src/login.ts:587`) and waits on
its loopback listener (`server.listen(0, "127.0.0.1")`, `src/login.ts:531`;
default timeout 300 s, `:591`). The attended path makes exactly two
control-plane HTTP calls before persist: discovery GET
(`src/tunnel.ts:211`, `${serverUrl}/.well-known/oauth-authorization-server`
— the sole discovery path) and token POST (`src/login.ts:642`). `/authorize`
is serviced to the curl client, never fetched by the driver.

Procedure:
1. Start the local mock with **exactly three endpoints**:
   - `GET /.well-known/oauth-authorization-server` — discovery document;
   - `GET /authorize` — 302 redirect to the request's `redirect_uri` with
     a code + echoed `state`;
   - `POST /token` — token JSON (PKCE verifier need not be validated).
   Log every request received. The mock is a ~50-line Bun script committed
   under `scripts/` for Skeptic reproducibility — it is not product code
   and mints no copy.
2. Launch the real pi host in tmux with `PI_REMOTE_SERVER_URL` pointing at
   the mock; `/rc:login`; press **empty-Enter** at the prompt (a real
   keystroke in the real host — never a fixture
   `accept:inputPrompt -> ""` injection, which bypasses the loopback
   listener and is the wrong seam).
3. Parse the printed authorize URL from the `-J` capture (widen the pane
   first so the URL does not truncate; `-J` joins wrapped lines), then
   `curl -sL` it — curl follows the redirect into the driver's own
   loopback listener; the driver exchanges the code at `/token` and
   persists.
4. Assert the mock's request log contains only the three expected
   requests (any unexpected request falsifies).
5. Byte-compare: `cmp <(jq -r .serverUrl <configDir>/pi-remote/credentials.json)
   <(printf %s "$PI_REMOTE_SERVER_URL")` must exit 0.

**Epistemics (record language):** the mapping empty-Enter →
`serverUrl === resolved` is guaranteed by construction
(`index.ts:688` → `login.ts:673`/`:902` → `credential.ts:212`
`writeAtomic`, no normalization; the read-side validator at
`credential.ts:233-238` is a corruption guard only). The mock run does not
discover the mapping; it discharges the non-construction residue — that
the whole attended chain *runs* at the installed host: env propagation
into the real pi process, loopback listener binding, discovery → authorize
→ token against live HTTP, atomic 0600 write into the real configDir. The
record says exactly this: "construction re-derived as boundary
observation," never "discovered."

**Redaction:** the credential bytes quoted as evidence carry only the
`serverUrl` field — tokens redacted.
