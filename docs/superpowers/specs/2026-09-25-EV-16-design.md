# EV-16 Design — Make `--headless` discoverable from the `/rc:login` command surface

**Card:** `council/cards/EV-16.md` · **Epic:** EPIC-7 · **Path:** full council (Deliberate), surface-touching
**Deliberation record:** `council/cards/EV-16-deliberation/` (three rounds + skeptic attack + consolidator synthesis)

## Goal (card verbatim)

The `/rc:login` command is registered with a description containing `--headless` and the
condition it is for (a remote machine with no usable browser); an attended login whose
`openUrl` fails routes to the `login.failure.browserOpenFailed` line, whose English row names
`/rc:login --headless` as the remedy; `rc` and `rc:off` descriptions do not contain
`--headless`.

## Binding constraints (do not reopen)

- **Phase-1 fixed row.** `login.failure.browserOpenFailed` English row reads **exactly**:
  `Could not open a browser — on a remote machine run /rc:login --headless. No credentials were saved.`
  (Replaces the current row at `src/login.ts:135-139`.)
- **Acceptance substrings.** The `rc:login` registered description must contain the literal
  `--headless` and the condition phrase `remote machine with no usable browser`; `rc` and
  `rc:off` descriptions must NOT contain the substring `--headless`.
- **Phase-1 surface-copy delegation.** Exact wording of the three descriptions was settled by
  the shared design pass; the outcome below is that settlement.

## Settled design

### 1. Registered descriptions (exact English strings)

| Command | Description |
| --- | --- |
| `rc` | `Start the remote tunnel — if not enrolled, run /rc:login first.` |
| `rc:off` | `Stop the remote tunnel.` |
| `rc:login` | `Enroll this host — use --headless on a remote machine with no usable browser.` |

(Contingency, implementation detail only: the settled string is already the short form — do
not lengthen it. The owner's longer r3 candidate `Enroll this host with the control plane —
…` was explicitly yielded and must not ship.)

### 2. Threading the description through the command surface

- Widen the internal controller dep `RemoteControllerDeps.command` (`index.ts:121`) from
  `(name, handler) => void` to `(name, handler, opts: { description: string }) => void` —
  **required**, so an undeclared description is a compile error at the three call sites
  (`index.ts:714-716`). (Skeptic O7(2) correction: the widening bites at call sites — TS2554
  — not at the stand-in lambdas, which stay legal TypeScript.)
- The production entry (`index.ts:939-944`) forwards `opts.description` into
  `pi.registerCommand(name, { description, handler })` instead of the hardcoded
  `description: "pi-remote"`. The real SDK member already declares
  `description?: string` (`RegisteredCommand`, installed `types.d.ts:963-969`, mirrored at
  `index.ts:74-78`) — this is **not** an R-TYPE re-diff; only the internal dep widens.

### 3. Test-harness widening (declared for card and PR — Acceptance 1)

- `test/index.test.ts`'s two harnesses (lines ~249, ~491): capture the description into an
  exposed `commandDescriptions: Record<string, string>`; assert `rc:login`'s contains
  `--headless` and `remote machine with no usable browser`; assert `rc` and `rc:off` do not
  contain `--headless`.
- `test/pi-sdk-load.test.ts`'s strict Proxy (lines ~68-72, currently `void opts`): capture
  `opts.description` and assert the same pins — this is the **real-boundary** assertion the
  card requires (the load smoke exercises the real `registerCommand` member).
- `test/login.test.ts`: failing-`openUrl` (resolves `false`, and a rejecting variant) →
  exact Phase-1-fixed row printed, **no** `login.attended.fallback`, **no**
  `login.attended.waiting`, outcome `{ kind: "failure", reason: "browserOpenFailed" }`, no
  credential written; absent-`openUrl` → `fallback` + `waiting` print, **no** `opening`
  line, no failure row (pins the absence semantics and the conditional-opening fix).

### 4. `openUrl` contract (driver change, `src/login.ts` `runAttendedLogin`)

- **Absent `openUrl` ⇒ proceed.** Skip the `opening` print (make
  `login.attended.opening` conditional on `deps.openUrl` being present — today `:535` prints
  "Opening your browser…" with no opener wired, false copy), print `fallback` + `waiting`,
  wait. Grounded: production never supplies `openUrl` (only `index.ts:116` type and `:680`
  passthrough); absence-as-failure would emit false copy on every production attended login.
- **Present and resolves `false` or rejects ⇒ fail fast:** print
  `login.failure.browserOpenFailed` (Phase-1-fixed text) and return
  `{ kind: "failure", reason: "browserOpenFailed" }` — a `LoginReason` member that already
  exists (`src/login.ts:54`). No credential is written.
- **Ordering (Acceptance 3):** the `openUrl` attempt moves BEFORE the `fallback` print.
  Failure path prints only the failure row — no `fallback`, no `waiting` — because the
  `finally` closes the loopback server and discards verifier/state, making the pasted URL a
  dead remedy (Copy Honesty Doctrine). Success path: `opening` (if opener present) → attempt
  → `fallback` → `waiting` → wait, byte-identical to today's success output.
- **Production dormancy:** no opener is wired in this card. The failure branch is
  fixture-reachable only. Opener wiring is a separate follow-up card (see Follow-ups).

### 5. Copy-boundary mechanics (`src/copy.ts`)

- `login.failure.browserOpenFailed` stays **out** of the id overlay (all `login.failure.*`
  rows are English-under-every-locale by the COVERAGE BOUNDARY design). No key change; pin
  with `indonesianCopy["login.failure.browserOpenFailed"] === undefined`.
- Add a COVERAGE BOUNDARY sentence naming the three command descriptions as new English
  surface (English-under-every-locale, no id rows).
- `login.cancelled` (`src/login.ts:201`) is unchanged and out of scope.
- The pre-existing "22 settled keys" comment drift is FLLWUP-42's, not this card's.

### 6. Spec sync (Spec Correction Governance — prose-sync, evidence-cited)

`docs/PI-SPEC.md` §7.2 (attended bullet, ~line 289) and the §8 `/rc:login` row (~line 411)
claim attended login "opens the default browser". The code does not and, after this card,
does not pretend to: correct the prose to state that the host attempts a browser open only
when a host-side opener is available, that without one the authorize URL is printed for
manual use, and that `--headless` is the remedy when no browser can reach the loopback. The
PR names the correction with its evidence (production `openUrl` is unpopulated; runtime
probe showed the false copy).

### 7. PR claims discipline (the PR description must state)

- MAY claim: dep-level failure branch implemented and fixture-reachable; the registered
  description is the production user-facing fix; the conditional `opening` line; the
  attempt-before-fallback reorder; the harness widening; the spec prose-sync.
- MAY NOT claim: `browserOpenFailed` is reachable by a real user today, or that a production
  attended login attempts a browser.
- MUST name: the production dormancy and its reason (no opener wired), the opener-wiring
  follow-up card, and the PI-SPEC correction with its evidence.
- Byte-diff named (Acceptance 3): on injected `openUrl` failure the output gains the
  Phase-1-fixed row and loses `Waiting for browser…` (and `If the browser does not open,
  visit: …`); the absent-`openUrl` path loses `Opening your browser…`; the success path with
  an opener is byte-identical to today.

### 8. Explicit exclusions (R-TYPE-1 discipline)

- **No opener wiring** in EV-16 (follow-up card).
- **No `getArgumentCompletions`** in EV-16; a future card adding it owes the explicit
  R-TYPE-1 re-diff (Acceptance 4).
- **No EV-17 implementation** here. EV-17's settled design-pass outcome (affordance
  `ctx.ui.confirm(title, message, { signal })` via a `waitForCancel` dep; wait line
  unchanged; cancel line unchanged; dialog copy `Waiting for browser…` / `Cancel sign-in?`)
  is recorded on EV-17's card and implemented by EV-17.
