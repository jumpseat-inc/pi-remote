# EV-3 Design Spec — Outbound wss transport with seq-ack envelope

Card: `EV-3` (EPIC-1) — "Outbound wss transport with seq-ack envelope"

Status: settled by Council deliberation (3 rounds, converged on a ten-point
architecture), Skeptic step-4 probes (O4/O6/O7/O8/O9 closed-green by running;
O1/O2/O3 open→closed/deferred below), and product-owner rulings (Sub-questions
1–4 + Companion R3) applied and binding. This file is the **complete** design.
If anything here is ambiguous, the design is wrong — so it is not. The owner
reads only this file plus the card's `Intent`/`goal`/Acceptance.

Binding contracts the design inherits (unchanged by any merged card): spec
§6 (envelope `{v, seq, ack, frame}`, monotonic extension-owned seq, ack echoes
the highest processed inbound seq, heartbeat, exponential backoff + jitter,
session id as logical connection id, durability split, idempotency);
`ctx.sessionManager.getSessionId()` (stable) and `ctx.ui.setStatus("pi-remote",
…)` are the only extension surfaces this card may touch — and **transport does
not call `setStatus`** (see §1.1); tunnel.ts (EV-2, merged) validates and hands
`{tunnelId, url, expiresAt}`; no other module performs network I/O; tests must
not require a real relay — stub/fake the WS server in-repo (Bun native
`WebSocket`); the 40-test suite stays green and this card adds its own.

## 0. What the card is

Implement `src/transport.ts` — the single WS network module that dials the
relay over `wss://`, wraps every AG-UI event in a `{v, seq, ack, frame}`
envelope with a monotonic extension-owned `seq`, echoes the highest processed
inbound `seq` as `ack`, heartbeats, and reconnects with capped exponential
backoff + jitter under a stable session-scoped connection id. It is the single
producer owning the total order that makes §9's 1:N fan-out workable. No other
module performs network I/O; history/inject do not exist yet so the
no-socket gate is enforceable only on `translate.ts` today (O3 — inherited by
EV-5/EV-6).

**Files touched by the PR:** `src/transport.ts` (new), `test/transport.test.ts`
(new), `docs/superpowers/plans/2026-08-31-EV-3-implementation.md` (new, the
owner's plan). Nothing else. **No edit to `docs/PI-SPEC.md` §8** (Companion R3
deferred to FLLWUP-2).

## 1. Architecture (binding)

### 1.1 The typed state-event seam — transport emits, EV-8 renders

Transport is a **transducer, not a renderer**. It emits a strictly-ordered,
severity-tagged stream of typed transport-status events; EV-8 alone calls
`ctx.ui.setStatus("pi-remote", …)`.

**The transport never calls `setStatus`, never returns/emits a footer state,
and never writes the footer.** The `error` footer state is EV-8's merge
decision, derived from transport reason metadata + tunnel.ts reason rows via
EV-8's merge function (ruling Sub-question 4). Transport has no path to a
footer write, by construction.

Typed event shape (ruling general rule + converged architecture #1/#10):

```ts
export type TransportKind = "dialing" | "live"; // CLOSED — no "error" kind exists
export type TransportReason =
  | "first_connect"      // payload: reason on the initial /rc dial
  | "reconnecting"       // payload: reason on dial attempts ≥ 2
  | "relay_unreachable"  // a dial failed (TCP/TLS/WS handshake) → reason on the NEXT dialing
  | "protocol_violation" // an inbound frame was malformed → reason on the NEXT dialing, after closing the offender
  | "url_expired";       // the re-armed URL's expiresAt passed before upgrade → reason on the NEXT dialing

export interface TransportStatusEvent {
  kind: TransportKind;            // dialing | live — the only two kinds
  connectionId: string;           // = session id (stable logical connection id)
  severity: TransportSeverity;    // EV-2 tag convention ("error" | "live" | "resyncing")
  order: number;                  // monotonic gap-free ordinal, so EV-8 can implement either merge rule
  reason?: TransportReason;       // closed 5-value taxonomy, always present on dialing
  attempt?: number;               // dial attempt ordinal (1 = first connect)
  since?: number;                 // wall-clock (injected now()) when the state began
}
export type TransportSeverity = "error" | "live" | "resyncing"; // EV-2 convention
```

The `reason` taxonomy above is **closed — these five are the only `reason`
values the transport ever emits** (ruling Sub-question 3; same closed-
vocabulary discipline as EV-1 Q2 applied to footer states). New reasons require
a spec amendment, not an implementation choice.

The field set floor is binding: `severity` and `order` are always present (EV-2
Item 4 merge-policy preference needs them). The residual fields
(`connectionId`, `reason?`, `attempt?`, `since?`) are settled to the shape
above by the converged architecture; **O2 — whether that shape lets an EV-8
merge function implement EV-2 Item 4's recorded preference "highest-severity-
wins for the live/error/dialing transitions" — is closed by the step-9 Skeptic
merge-policy fixture** (see §3.2), not by this spec. The owner implements the
shape above exactly; it must not starve the shape (a field-starved event set
would fail the fixture).

### 1.2 Retry-forever at capped exponential backoff + jitter (Sub-question 1)

The reconnect loop **never gives up** for the life of the transport instance.
After a network close/error, the transport enters a backoff loop that runs
until the session ends. There is no `relay_unreachable`-after-N counter inside
the transport that transitions it into a permanent failure mode, and no
give-up boundary. The backoff is **exponential with full jitter, capped**:

- `delay(attempt) = min(backoffMax, backoffBase * 2^(attempt-1))` as the ceiling,
  with **full jitter** `rand(0, ceiling)` (standard exponential-with-full-jitter
  with a cap). The cap value (`backoffMax`) is implementation-defined and lives
  in this card's acceptance tests, not in a ruling.
- Backoff **resets on a successful open** (`live`).
- The cap and base are injected params (defaults in the module, overridable).

**`disconnect()` — a local close — must NOT auto-reconnect.** `/rc:off` and the
`session_shutdown` handler map to a local close (teardown); a relay/network
death maps to a network close (reconnect). The transport must distinguish a
deliberate local close from a network-close and only auto-reconnect on the
latter (principal's testable claim; see §3.1).

### 1.3 The three-numbers seq/ack contract (converged #5/#6)

Three distinct numbers, never conflated:

- **`outboundSeq`** — extension-owned monotonic counter, incremented once per
  emitted envelope, **never reset within the transport instance, including
  across reconnects**. In-memory; it dies with the session epoch (process
  restart = a new epoch, recoverable by event-id dedupe, never by seq).
- **`inboundSeq`** — the inbound watermark: highest inbound envelope `seq` the
  transport has **dispatched** to its inbound consumer ("processed" = dispatched,
  not applied — transport cannot know whether `inject` succeeded). This is the
  `ack` the transport stamps on outbound envelopes.
- **`lastAckedSeq[deviceId]`** — per-device record of the highest *outbound*
  seq that device acked (from its inbound `ack`), §7.3. **Read-only data the
  transport hands to EV-5** for replay scoping. Not part of the outbound
  envelope.

Envelope shape and rule:

```ts
export interface TransportEnvelope {
  v: 1;
  seq: number;   // outboundSeq, monotonic
  ack: number;   // inboundSeq watermark (highest processed inbound seq)
  frame: AgUiFrame | null; // an AG-UI event; the envelope is { v, seq, ack, frame }
}
```

- **`seq` assigned at write time.** Assign inside `send` immediately before the
  socket write, so a `send`-while-not-live **drop emits a signal and never
  consumes a seq** — a dropped frame is never emitted, which deletes the gap
  ambiguity by construction. Invariant to hold: **"consecutive over emitted
  frames."**
- Envelope `ack` = **socket-level watermark** (max dispatched inbound seq on the
  relay→extension socket). The envelope has **no `deviceId` field**, so the
  outbound `ack` can only be the socket watermark, never per-device (with 1:N a
  per-device ack in the broadcast envelope would ack the wrong device and break
  §5.3 resume). Because the outbound broadcast `ack` is a single number, the
  **inbound seq space must be global across all devices**.
- Per-device `ack`/`lastAckedSeq[deviceId]` is derived from **inbound envelopes**
  (which, per §7.3, carry the sending `deviceId`) and is read-only data for
  EV-5.
- On inbound, the transport rejects malformed envelopes (bad shape, non-numeric
  seq, ack inversion). A `protocol_violation` closes the offending socket and
  surfaces as `reason: "protocol_violation"` on the next `dialing` event.

The durability split and idempotency stand: the extension keeps **no durable
buffer beyond the in-flight window** (sent-but-unacked); the local JSONL is the
source of truth. Live frames carry UUID event ids (stamped by transport via an
injected `newId`, see §1.5); replay frames carry EV-5's deterministic ids and
must be left untouched.

### 1.4 Reconnect & re-arm seam (converged #4)

A reconnect re-binds to the **same session id** (`sessionId`), never spawning a
new tunnel at the session layer. Because the signed one-time URL is consumed on
successful upgrade (§7.2), every reconnect after a real socket drop needs a
**fresh** re-arm call.

- **Transport owns WHEN, EV-8 owns WHAT.** Transport invokes the injected
  `rearm(): Promise<CreateTunnelResult>` **once per dial attempt ≥ 2, inside the
  backoff loop (after the backoff sleep)**. First connect does **not** call
  `rearm` — EV-8 hands the initial `{url, expiresAt}` from its own `/rc`
  `createTunnel`.
- The `rearm` closure is EV-8's to author: best-effort `deleteTunnel(currentTunnelId)`
  → optional silent refresh → `createTunnel(...)` → update `currentTunnelId`.
  Transport never imports `tunnel.ts`, never sees a credential, never calls
  `fetch` (see §1.6).
- Transport re-checks the URL is `wss:` (defensive) and **refuses to dial past
  `expiresAt`** (injected `now()`); a URL whose `expiresAt` passed before the
  upgrade completes surfaces as `reason: "url_expired"` on the next `dialing`.
- `getId()` returns the session id, full stop; transport never assumes
  `tunnelId` is stable across attempts.
- Re-arm does **not** trip EV-8's idempotency guard: EV-2 converged that guard
  is keyed on "live", not "ever-created". The tunnelId churn / superseded-
  `DELETE` accounting is EV-8's post-change gate, not an EV-3 obligation; leak
  is bounded by §7.2 (single-use token + TTL).

### 1.5 Heartbeat — native WS control-frame ping (converged #3, Skeptic O4 green)

Heartbeat is a transport-level **WS control-frame `ping`** below the framing
layer — the server accepts "AG-UI frames and nothing else", and a
proxy-surviving heartbeat must be a control-frame ping (which arrives at the
server's `websocket.ping` handler, not the `message`/AG-UI data path). Settled
by a running probe on Bun 1.4.0 (Skeptic O4 closed-green): the Bun client
`WebSocket` **has a callable `.ping()`** (tsconfig `lib` is `ESNext` + `types:
["bun"]`, no DOM → resolves to `Bun.WebSocket`), and pings hit the server's
`ping` handler, not `message`.

The Bun client has **no `pong` event** (`close | error | message | open` only),
so **dead-peer detection rides `close`/`error` + the next failed `send`**, not a
pong-timeout. The heartbeat's testable job is **keep-alive** (a fake relay
`idleTimeout` smaller than the heartbeat interval; assert `readyState === OPEN`
well past idle, with pings recorded server-side). Heartbeat cadence params
(`heartbeatInterval`, `idleTimeout`/proxy-timeout) are injected with defaults.

### 1.6 Injection & purity guards

- `send(frame: AgUiFrame): number | null` — returns the assigned `seq` on emit,
  or `null` on a drop-with-signal while not live (no queue). Every live frame
  gets a UUID `frame.id` via injected `newId`; **`send` must leave a pre-existing
  `frame.id` untouched** (replay frames carry EV-5's deterministic ids —
  stamping over them would break replay dedupe). The transport is the **sole seq
  assigner**: EV-5's replay and live frames both go through `transport.send()`;
  `uptoSeq` for `resync_done` is whatever `send` returned.
- Transport is a **pure-ish state machine with injected seams** — all network,
  clock, and randomness are injected: `{ WebSocket, now, sleep, rng, newId,
  rearm, onEvent, onInbound }`. No module-level mutable state (importing
  `transport.ts` has no side effects). **No `fetch(` anywhere in
  `src/transport.ts`** (it is the WS-only module; tunnel.ts owns `fetch`).
- No other module performs network I/O. Static guard test asserts
  `translate.ts` contains no `new WebSocket(` / no `wss?://` dial (the only
  no-socket gate enforceable today — O3). history/inject inherit this in
  EV-5/EV-6.

## 2. Public surface the owner implements (for downstream consumers)

The owner implements and **exports** from `src/transport.ts`:

```ts
// deps injected by the caller (EV-8 wires rearm + sessionId + onEvent + onInbound;
// EV-5/EV-6/EV-8 consume the handle).
export interface TransportDeps {
  sessionId: string;
  rearm: () => Promise<CreateTunnelResult>;   // EV-8-authored closure (DELETE → refresh? → createTunnel)
  WebSocket: typeof WebSocket;
  now?: () => number;
  sleep?: (ms: number) => Promise<void>;
  rng?: () => number;                          // [0,1) for jitter
  newId?: () => string;                        // UUID gen for live-frame ids
  onEvent: (e: TransportStatusEvent) => void;
  onInbound: (frame: InboundEnvelope) => void;
  // backoff / heartbeat params (defaults in the module)
  backoffBase?: number;
  backoffMax?: number;
  heartbeatInterval?: number;
  proxyTimeout?: number;
}

export interface TransportHandle {
  connect(initial: { url: string; expiresAt: number }): Promise<void>; // first connect; does NOT call rearm
  disconnect(): Promise<void>;            // LOCAL close → MUST NOT auto-reconnect (idempotent)
  send(frame: AgUiFrameLike): number | null; // assigned seq, or null on drop-with-signal while not live
  getId(): string;                        // session id (stable logical connection id)
}

export function createTransport(deps: TransportDeps): TransportHandle;
```

The exact function name (`createTransport`) and the exported type names are
binding so that EV-8/EV-5/EV-6 import against a stable contract. `AgUiFrameLike`
is the AG-UI frame shape as declared in `translate.ts` (the repo has no AG-UI
SDK dependency; transport imports the frame type only).

## 3. Gate plan (step 8 owner) and step-9 closure-by-test

### 3.1 Owner gates (unchanged, full-strength regardless of change size)

This card's gate set is: **typecheck** (`bunx tsc --noEmit`) and **tests**
(`bun test`), with the **40 existing tests staying green** and transport's own
tests added. **No Mongo, no real relay** — WS server is stubbed/faked in-repo
via Bun native `WebSocket` (`Bun.serve`). This is the same gate set CI runs
(`.github/workflows/gates.yml`). (The generic owner agent's Mongo/import-smoke/
boot gates do **not** apply to this repo; the gates above are the authoritative
set.)

Transport-specific tests the owner writes (mapping the card's Acceptance):

1. `envelope(...)` (pure) returns exactly `{v: 1, seq, ack, frame}`; N outbound
   frames yield strictly increasing consecutive `seq`; inbound `seq = k` updates
   the next outbound `ack` to `max(k, …)`.
2. `nextBackoff(attempt, {base,max}, rng)`: with fixed `rng = 1` (full jitter)
   returns `min(max, base * 2^(attempt-1))`, strictly increasing until `max`; with
   uniform rng lands in `[0, computedCeiling]`; resets after a successful open.
3. On relay kill (network close): transport calls `rearm()` for a fresh URL and
   re-dials; `getId()` unchanged across reconnect; non-decreasing measured
   `now()` deltas; **backoff loop never exits on its own** (retry-forever, O1).
4. During reconnect, `onEvent` sees `{"kind":"dialing", reason:"reconnecting"}`
   then `{"kind":"live"}`; **never** a `kind:"error"` event; reason values drawn
   from the **closed 5-value set** (O1).
5. Every live outbound frame carries a UUID `frame.id` (regex, distinct); a
   pre-existing `frame.id` is left untouched (replay). Static check:
   `translate.ts` has no `new WebSocket(`/`wss?://` dial (O3).
6. Heartbeat: fake WS answers pings → after idle `> proxyTimeout` the socket is
   still OPEN with pings recorded server-side; close/error or a failed `send`
   (dead peer) tears the connection down and reconnect fires.
7. Local `disconnect()` does **not** auto-reconnect; network close does (the
   two-close-types distinction).
8. `transport.ts` contains no `fetch(`; importing it has no side effects
   (no module-level mutable state).
9. The **typed event shape** — see §3.2, the O2 merge-policy fixture.

## 4. Downstream contract (what EV-5/EV-6/EV-8 inherit — for record)

Per the ruling's general rule: the transport failure signal is **honest
metadata, never terminal**. EV-8 reads the transport's typed event stream and
decides when a `dialing` reason (`relay_unreachable`|`protocol_violation`|
`url_expired`) lands the footer on `error`, and how to render `first_connect` vs
`reconnecting`. EV-5 pushes replay frames through `transport.send()` and reads
transport-reported `uptoSeq`; `send`-while-down is a drop with a signal, and any
user-facing "could not replay" copy is an EV-8 render, not a transport
emission. EV-6 injection is local; a remote-didn't-see-it failure is an EV-8
rendering concern. EV-7 runs before the transport exists and does not read this
ruling. None of these cards ship on the EV-3 PR.
