## Intent

The resolved control-plane URL is baked into the prompt title today and the
extension passes `ui.input` only its title argument; the documented
`placeholder` argument is dropped at `RemoteControllerDeps.inputPrompt` and at
the entry wiring. This card widens the dependency and the wiring to forward the
resolved URL as the placeholder, while leaving the title byte-unchanged: the
installed host discards the placeholder, so the title remains the rendered
consent surface and the URL never leaves it. "Resolved" keeps EV-15's meaning —
the env → setting → stored credential → literal-default tier — so on an enrolled
host the forwarded placeholder is that host's stored URL, not the literal
default. The replacement-confirm prompt is URL-less and receives no placeholder;
empty-submit and Escape-cancel semantics stay behaviorally unchanged. The
placeholder-discard residual is carried in the card record and PR description.

## Acceptance

1. `RemoteControllerDeps.inputPrompt` is widened to
   `(prompt: string, placeholder?: string) => Promise<string | undefined>`, and
   its annotation carries the real SDK signature
   `input(title, placeholder?, opts?: ExtensionUIDialogOptions)`
   (declare-or-annotate); the entry wiring forwards both arguments to
   `ctx.ui.input`.
2. The attended URL prompt call passes the resolved URL as the placeholder
   argument, byte-equal across all four resolve tiers (extending the existing
   tier matrix), and the prompt title is asserted byte-unchanged — still
   containing `[${resolved}]` and the consent sentence (regression guard: the
   URL never leaves the rendered surface).
3. Empty submission enrolls against exactly the resolved URL; typed input
   enrolls against the typed value; `undefined` (Escape) cancels with no driver
   constructed — pinned in the same matrix update.
4. The replacement-confirm prompt passes no placeholder.
5. PI-SPEC's prompt description (§7.2/§8) is updated in the same PR to note the
   placeholder pass-through; `src/copy.ts`'s boundary comment is corrected only
   where its prompt citation has gone stale; no copy key is added, changed, or
   removed (FLLWUP-41 unaffected).
6. The residual is named in the PR description and card record: installed pi
   0.87.1's `ExtensionInputComponent` discards `_placeholder`, so no greyed
   in-box render occurs on the installed host; the title is the rendered
   fallback until a host honors the signature.

### Round 1 — designer

**Design position** — Forwarding the resolved URL as `ui.input`'s second argument is the right move: it is purely additive on the installed host (zero rendered change because pi 0.87.1's `ExtensionInputComponent` discards `_placeholder`, per PO ruling 2026-09-27 and EV-15's closed-green O5), and on a future host that honors the documented signature `input(title, placeholder?, opts?)` it would render the same value a third time — at the input site, where the eyes already are. That third repetition is **consistent with the title's pre-existing redundancy** ("Control-plane server URL [<resolved>]:" already names it, the consent sentence "Press Enter to enroll this host against <resolved>…" names it again), so it is not a new comprehension pattern; it is the standard HTML-input-plus-label "Enter accepts the greyed hint" convention applied to a single value. The replacement-confirm prompt correctly passes no placeholder — that prompt is about credential state, not URL — and the title remains the rendered consent surface today.

**Gulf closed** — Gulf of Execution, for a person who runs `/rc:login` on a host that honors the SDK signature: today the URL lives only in the title; after, the URL also lives at the input site, so the person who has already moved their eyes into the box sees the default they will accept by pressing Enter without re-reading the title. On the installed host (pi 0.87.1), the Gulf is unchanged — and that is the right trade, because the title carries the consent surface byte-unchanged (Phase-1 ruling, class "surface copy"), and EV-19 verifies the actual host render and records the anticipated negative.

**Principle and evidence** —
- **Signifier / mapping.** The title is already a *paired* signifier — bracketed URL plus a stated action ("Press Enter to enroll … or type to override"). Adding the placeholder as a third copy of the same value does not change the mapping; it reinforces the only mapping that exists (consent surface = resolved URL). The placeholder is a *near-input* signifier, and convention (HTML `<input placeholder>` everywhere) treats near-input greyed text as "this is what you'll get if you do nothing," which exactly matches "Press Enter to enroll this host against <resolved>]." Evidence: `index.ts:672-674` is the title literal that already says the URL twice; the proposed `placeholder` arg would equal the same string verbatim. The seam is widened at `index.ts:107` (`inputPrompt: (prompt: string) => …` → `(prompt: string, placeholder?: string) => …`) and at `index.ts:973` (`(prompt) => requireCtx().ui.input(prompt)` → `(prompt, placeholder) => requireCtx().ui.input(prompt, placeholder)`), matching the vendored SDK signature at `src/pi-sdk-on.ts:31-32` and `docs/PI-SPEC.md` is sync-updated at §7.2/§8 per Phase-1 ruling (class "surface copy").
- **Constraint / forcing function (on the title).** The title's bracketed `[<resolved>]` form is the consent surface that cannot be removed (PO ruling 2026-09-27, Copy Honesty Doctrine, FLLWUP-41's `login.urlPrompt` keyed settlement). It is what the person sees on every host, today and tomorrow; removing it would erase the URL from the only surface the installed host renders. The card is correctly named "Render … as the attended /rc:login input **placeholder**" — not "Replace the title with …" — and the binding ruling pins that the title stays byte-unchanged.
- **Affordance vs. signifier (the comprehension check the card asks for).** A user on a future-honoring host sees: (1) bracket default `[https://…]` in the title, (2) "Press Enter to enroll this host against https://…" in the title, (3) greyed `https://…` inside the box. The reading order is title → box; the title's explicit "Press Enter = use; type = override" sentence resolves any ambiguity about *whether to type* — the placeholder's greyed hint answers *what typing would replace*, which is the conventional pairing. No new mental model is required: "what the box would say if I did nothing." That is what an input placeholder has always meant.
- **Honest residual.** The placeholder is *expected not to render* on the installed host (EV-19's documented acceptance: "the placeholder is anticipated NOT to render greyed on pi 0.87.1, and that recorded negative is the card's honest success"). That honesty is the *only* thing that makes forwarding the argument safe today — if a host that did render it would mislead, the argument would be a hazard; because no installed host renders it, the seam widening is free.
