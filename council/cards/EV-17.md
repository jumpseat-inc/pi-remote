## Intent

`cmd.cancel()` exists one layer down and nothing calls it; the attended flow can only end by
code, mismatch, or a five-minute wait. The surface the user stares at during that wait
(`login.attended.waiting`, `"Waiting for browser…"`) offers no exit. The card first settles
which affordance is honest in the pi TUI — a keypress escape, a confirm, or another
in-session action — which is why it stays Backlog until the shared design pass with EV-16
names it.

## Acceptance

1. The affordance is a named, reproducible action settled in the card's final design; the test
   drives exactly that action through the injected seam and asserts `{ kind: "cancelled" }`
   plus the single exact line, with zero token-endpoint or device-endpoint requests after the
   signal.
2. Discriminating timing assertion: measured elapsed wall-clock is strictly less than the
   injected `redirectTimeoutMs` — the test distinguishes an interrupt from a reason-flip at
   timer fire.
3. The test uses a small injected `redirectTimeoutMs` and proves the cancel path, not the
   timeout path.
4. No credential file is written or modified.
5. The dead cancel branches are resolved: either `runAttendedLogin`'s
   `callback { type: "cancelled" }` becomes reachable, or it is removed;
   `createLoginCommand.cancel()` is either wired to the surface or documented as a
   headless-only seam.
6. Wait-state and cancel copy is settled in the one shared design pass with EV-16 (card-level
   constraint); promotion to Ready requires it.
## Shared design pass (EV-16/EV-17) — recorded outcome (run 2026-09-25)

Settled by EV-16's working seats (record: `council/cards/EV-16-deliberation/`; synthesis
S8/S9 in `consolidator-synthesis.md`). EV-16's card state only — this card's `state`
remains `Backlog` pending `product-owner` promotion ratification.

- **Affordance (Acceptance 1, 5):** `ctx.ui.confirm(title, message, { signal })` — a real
  installed SDK member (Skeptic O1 closed-green: `types.d.ts:72-73`, `signal?: AbortSignal`
  at `:39`; scratch compile probe exit 0). Wired as a `LoginDeps.waitForCancel?:
  (signal) => Promise<boolean>` dep implemented as
  `requireCtx().ui.confirm("Waiting for the browser…", "Cancel sign-in?", { signal })`,
  re-armed on `false` until the signal aborts; the driver races it against the callback
  wait; confirm-cancel settles the callback with `{ type: "cancelled" }` (making the
  currently-dead branch reachable — Skeptic O7(3) proved it unreachable at base by runtime
  probe); the callback winning aborts the signal to dismiss the dialog; `cancel()` must
  wake the wait, not just flip a flag, and clear the timer to prevent a duplicate timeout
  settle. A registered `/rc:login:cancel` command was rejected on evidence: a command typed
  mid-wait cannot dispatch (Skeptic O2 closed-green — the host's input loop is parked in
  `session.prompt` until the login handler resolves), so it fails Acceptance 1 on timing.
- **Wait/cancel copy (Acceptance 6):** wait line UNCHANGED (`login.attended.waiting` =
  `Waiting for browser…`); dialog title `Waiting for browser…`, dialog message
  `Cancel sign-in?`; cancel line UNCHANGED (`login.cancelled` =
  `Sign-in cancelled — no credentials were saved.`, byte-exact at `src/login.ts:201`),
  printed exactly once by the facade, never by the driver. No new refusal line (the
  designer's proposed no-op line served the rejected command affordance).
- **Promotion precondition:** met — this block is the design pass EV-16's Acceptance 5 and
  this card's Acceptance 6 require.

## Step-6 rulings (product-owner, job-22 — binding, applied verbatim)

**Ruling:** Route **(a)** — extend the vendored `src/pi-sdk-on.ts` to declare `confirm` with the full real installed signature, `confirm(title, message, opts?: { signal?: AbortSignal; timeout?: number }): Promise<boolean>`, with line-referenced provenance to the installed `types.d.ts` and both optional members declared (the EPIC-6 declare rule — declare, do not omit). - Options rejected: (b) add the real SDK as a dependency — contradicts recorded doctrine ("The SDK is not a dependency; the vendored mirrors are the boundary", R-TYPE-1); (c) cast-based escape — violates the vendored bridge's cast-free discipline and R-PAYLOAD-1's correct-not-annotate default.
- Grounding: `vault/wiki/Real-Surface Verification.md`; `vault/wiki/pi-sdk-on.ts.md`; EPIC-6/FLLWUP-39 declare pattern.
- Reversibility: cheap — one vendored type declaration plus provenance comment.

### Q2 — Non-interactive host gating
**Ruling:** **Gate.** The `waitForCancel` dep is wired only where `confirm` can genuinely wait on a user. Where it is wired, its semantics are exactly the settled ones (re-arm on `false` until the signal aborts) — gating changes *presence*, not behavior.
- Options rejected: unconditional wiring (O-2 proved RPC `confirm` resolves `false` immediately → a live re-arm spin for the full `redirectTimeoutMs`); bounded re-arm (would reopen settled design text).
- Grounding: designer r1 open item 5; principal r2 §2; O-2. Not a portfolio matter — no steward escalation.
- Reversibility: very cheap — wiring in the `export default` closure. The gate must key on a real, verifiable host property, not a heuristic guess.

### Q3 — PI-SPEC §7.2 prose-sync scope
**Ruling:** **In-scope — it rides the implementing PR**, as facilitator-authored, evidence-cited prose-sync of the attended-flow bullet naming the new cancel affordance.
- Options rejected: follow-up card — that routing is for pre-existing drift in a surface the card does not own; here the prose goes stale because of this card's own change.
- Grounding: `vault/wiki/Spec Correction Governance.md` three-part test (forced; preserves security model; ownership).
- Reversibility: trivial — one sentence.
