# EV-16 — principal position

## Cross-seam reading (what the contract actually is, both sides open)

**Command-surface seam.** `index.ts:714–716` registers the three commands through `deps.command(name, handler)`. The controller dep type at `index.ts:121–122` is `(name, handler) => void` — **no opts slot**. The only place `description` exists is the real entry, `index.ts:939–944`, where it is hardcoded `"pi-remote"` for every command and forwarded to `pi.registerCommand`. So all three palette rows are byte-identical today; there is no path from a controller-level string to the palette without changing the dep type **and** the two stand-ins: `test/index.test.ts:249` and `:491` (`command: (name, handler) => …`, opts dropped) and `test/pi-sdk-load.test.ts:68–71` (`void opts`).

**openUrl seam — the finding.** `openUrl` appears in `index.ts` exactly twice: the optional dep declaration (`index.ts:116`) and the forward into the login driver (`index.ts:680`). The production entry (`index.ts:905–957`) never passes it. So in a real host `deps.openUrl` is `undefined`, `deps.openUrl?.(…)` at `src/login.ts:539` short-circuits, and the attended flow prints `fallback` (`:536`) + `waiting` (`:541`) and blocks on `await cbPromise` (`:550`) for 300s. Meanwhile `PI-SPEC.md:288–289` states `/rc:login` "opens the default browser" — **the code does not**.

**The card's failure line is dead.** `browserOpenFailed` appears in `src/login.ts` only at `:54` (union member) and `:135–136` (row). No code path returns `reason: "browserOpenFailed"`. `grep` proves it; the row is unwritten copy.

**The wait is not cancellable.** `runAttendedLogin` reads `ctl.cancelled` only *after* `await cbPromise` (`src/login.ts:551–553`); `createLoginCommand.cancel()` (`:893–895`) sets a flag and settles nothing. So EV-17's elapsed-time acceptance is unreachable today regardless of affordance: `cancel()` cannot wake the `cbPromise` wait. The `{ type: "cancelled" }` `CallbackResult` branch (`:555–557`) is dead for the same reason.

**Copy boundary.** `login.attended.waiting` (`:191`), `login.failure.browserOpenFailed` (`:135–138`), and `login.cancelled` (`:195`) live in `login.ts`. `src/copy.ts:1–40`'s COVERAGE BOUNDARY already declares login rows English-under-every-locale and enumerates keyless English literals — new command descriptions are new English surface and must be added to that boundary, not slipped in silently. Copy Honesty Doctrine applies ("name only remedies a real actor can perform"; `login.attended.fallback`'s old "visit the URL" is dishonest on a remote host, whose browser cannot reach `127.0.0.1`).

## Blind spots, named separately

- **Driver/pipeline vantage** (`src/login.ts` + `test/login.test.ts`): sees `openUrl` as an injected dep and can write a green acceptance-3 with a failing stub — never sees that the production entry supplies nothing, so `browserOpenFailed` stays unreachable in a real host. This is Fixture-Green Honesty / Real-Surface Verification: "reachable" must be pinned to the installed boundary, not the injected one.
- **Surface/command vantage** (`index.ts` registration + palette): can hardcode a better string into `index.ts:940` and see the palette update, but cannot see that the value has no route through the controller contract (`RemoteControllerDeps.command`) or the strict Proxy — so the assertion "at the real boundary via the load smoke" stays vacuous unless the dep + both harnesses are widened first.
- **Neither** sees that `openUrl === undefined` is itself a contract with hidden semantics. `deps.openUrl?.` currently encodes "no opener ⇒ proceed as if a browser opened" — the exact dishonest default the card exists to kill. Choosing its meaning is the card's real decision.

## Reframe

The card is framed as two strings. The actual seam is one contract with three coupled halves: **(1)** a description cannot reach the palette until `command` carries opts through the controller dep and both harnesses; **(2)** `browserOpenFailed` cannot be reachable until the entry supplies a real `openUrl` **or** the driver declares `undefined` semantics; **(3)** the "surface" and "driver" halves are joined by that `openUrl` contract. I propose the driver boundary make `openUrl` **required** (`(url) => Promise<boolean>`, not optional) and the entry supply a real platform opener as a `src/pi-host.ts` capability (`open` / `xdg-open` / `cmd /c start`, or `pi.exec`, a real member at `types.d.ts:1068`). Then "can't open a browser" is a genuine production condition on a remote host, `PI-SPEC §7.2` becomes true, and EV-16's line is reachable at the real boundary. If the seats judge opener-wiring out of scope, the honest alternative is the opposite: treat `undefined` as failure (immediate `browserOpenFailed`), which makes *every* attended login route to `--headless` and **requires correcting `PI-SPEC.md:288`** under Spec Correction Governance. What must not ship is `openUrl` left optional-and-unpopulated while the PR claims the line is "reachable."

**Open-url ordering.** `fallback` is printed at `:536` *before* `openUrl` runs at `:539`, so acceptance 3's "does not proceed to … `login.attended.fallback`" can only hold if the attempt moves *before* the fallback print. Position: print `opening` → attempt `openUrl` → on failure print `browserOpenFailed` and return (no `fallback`, no `waiting`); on success print `fallback` + `waiting`. This sacrifices the local manual-paste recovery, but `--headless` is performable by local and remote actors alike, so the ruled remedy is honest for both. If the seats want to preserve the paste-URL recovery, acceptance 3's wording must be narrowed to "does not proceed to `waiting`"; the card as written does not permit both.

## Design-pass items

**(a) Descriptions.** Exact strings I propose:
- `rc`: `Connect this session to the remote relay`
- `rc:off`: `Disconnect the remote relay`
- `rc:login`: `Enroll this host with the control plane — on a remote machine with no browser, use /rc:login --headless`

`rc:login` contains the literal `--headless` **and** names the condition (remote machine, no usable browser). `rc` / `rc:off` contain no `--headless`. Threading: `RemoteControllerDeps.command` gains `opts?: { description?: string }`; `deps.command("rc:login", rcLoginCommand, { description: LOGIN_COMMAND_DESCRIPTION })`; the entry forwards `opts` into `pi.registerCommand`; both stand-ins capture it. These are new English surface — add a COVERAGE BOUNDARY sentence in `src/copy.ts` naming the three command descriptions (English-under-every-locale, no id rows) rather than silently expanding the boundary.

**(b) EV-17 affordance.** The honest real-surface primitive is **`ctx.ui.confirm(title, message, { signal })`** (`types.d.ts:69–73`; `examples/extensions/timed-confirm.ts` proves `{signal}`/`{timeout}` auto-dismiss). A raw keypress escape is not an extension surface (`onTerminalInput` is interactive-only and global); a second command is untranslatable while a command blocks the editor. Wiring: add `LoginDeps.waitForCancel?: (signal: AbortSignal) => Promise<boolean>`, implemented in `index.ts` as `ctx.ui.confirm("Waiting for the browser…", "Cancel sign-in?", { signal })`; `runAttendedLogin` races it against `cbPromise`, aborts the signal when the callback wins (dismissing the dialog), and on cancel settles the callback with `{ type: "cancelled" }` — which makes the dead branch at `:555–557` reachable (EV-17 acceptance 5). `cancel()` must also settle/wake the wait, not just flip the flag. Terminal copy stays exactly `login.cancelled` = `Sign-in cancelled — no credentials were saved.` printed **once by the facade** (`:882–884`); the driver must not print it. `login.attended.waiting` stays `Waiting for browser…`; the dialog's title/body are the only new wait-cancel copy and go into the same boundary note. On a remote/no-browser host EV-16 exits before the wait, so EV-17's cancel serves the host where the browser did open — both are needed.

## Testable claims (Skeptic-runnable)

1. **Dead row.** `grep -n 'browserOpenFailed' src/login.ts` returns only `:54` (union) and `:135–136` (row); there is no `reason: "browserOpenFailed"` return. Falsifiable by grep.
2. **openUrl unpopulated in production.** `grep -n 'openUrl' index.ts` returns only `:116` and `:680`; therefore `entry(pi)` constructs the controller without `openUrl`. Structural test: build the entry against a recording host and assert no `openUrl` is ever constructed/passed. **Test to add:** with the current entry, assert the attended flow reaches `waiting` without any opener call — proving the reachability gap.
3. **Cancel cannot wake the wait.** Red-at-base test: call `runAttendedLogin(deps, null, ctl)` with `redirectTimeoutMs: 200`, set `ctl.cancelled = true` immediately, and assert no resolution within 50ms (it resolves only at 200ms). This fails today and is EV-17 acceptance 2's discriminating assertion.
4. **Descriptions collapsed.** `grep -n 'description' index.ts` shows the single hardcoded `"pi-remote"` at `:940`; the real-boundary smoke discards opts (`test/pi-sdk-load.test.ts:68–71` `void opts`). Test to add after widening: capture opts in the strict Proxy, assert `rc:login` matches `/--headless/` and `rc`/`rc:off` do not.
5. **Ordering.** With `openUrl` rejecting, assert the captured output does **not** contain `login.attended.fallback` or `login.attended.waiting`, and does contain `login.failure.browserOpenFailed`. This fails today (fallback prints at `:536` before the attempt) and pins acceptance 3 verbatim.
6. **Single cancel line.** With the cancel seam triggered, assert `login.cancelled` appears exactly once and no token-/device-endpoint request is logged (`loginEndpointRequestLog` is empty), and no credential file is written.
