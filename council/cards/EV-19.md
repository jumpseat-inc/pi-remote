## Intent

The installed pi distribution declares `input(title, placeholder?, opts?)` but
its interactive input component discards the placeholder, so the extension's
argument reaches a host that does not render it. Fixture tests over the injected
`inputPrompt` can prove the argument is forwarded, not what the host draws; a
real-host observation is the only way to record what the person actually sees.
This card carries that boundary observation for EV-18's user-visible surface,
treating the anticipated non-render as the honest result rather than a
surprise.

## Acceptance

Real-host run recorded: (a) transcript or screenshot showing whether the
placeholder renders, with the anticipated non-render recorded as the named
residual or, if a future host renders it, the greyed render and its clear-on-type
behavior observed and recorded (including backspace-to-empty dynamics,
conditional on a placeholder actually rendering); (b) the prompt title still
displays the resolved URL; (c) empty-Enter yields a persisted credential whose
`serverUrl` byte-equals the resolved URL; (d) any deviation from (a)–(c) is
recorded in the PR.

- Run the EV-18 P-E CDP smoke at the installed-host boundary: confirm no greyed in-box placeholder renders on pi 0.87.1

#### designer (round 1)

### Design position

The PR record is itself the only interface by which a future reader can perceive what pi 0.87.1 drew under the EV-18 seam, and "transcript or screenshot" is too loose a specification for a *negative* observation: a screenshot cannot be re-grepped, and a prose "the placeholder did not render" leaves a reader who *expects* HTML-style greyed placeholder text free to under-read it. The smallest change that closes the gulf is to require the record to carry the **raw pane bytes** (ANSI preserved), a **deterministic pointer** (line range / SHA-256) into those bytes, and a **signed negative observation** that names what was searched for and found absent — so a re-reader who never re-runs the experiment can re-derive the answer.
