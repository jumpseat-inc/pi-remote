## Intent

The data plane, on the page in full: the WS upgrade with the one-time token;
the envelope is exactly `{v, seq, ack, frame}` — four keys, no extension point;
`seq` is monotonic and **client-owned** (the server never reorders, renumbers,
or stamps); `ack` echoes the highest processed inbound seq; the server relays
and never interprets frames. The two server-to-client control frames are
specified exactly: `{type:"resume", deviceId, lastAckedSeq}` (client requests
catch-up) and `{type:"resync", fromSeq}` (server cannot serve from cache and
asks the client to replay) — plus the rule that these are the only control
frames on the wire, so a server needing more must version the protocol, not
improvise. Fan-out: 1:N to granted devices, identical ordered stream, per-device
bookkeeping only. Ring-buffer caching is best-effort and disposable (the client
replays from its own store when the cache misses) — stated as a MUST-not-rely
for the server and a SHOULD for capacity. Non-normative guidance: ring sizing,
connection state machine, backpressure, deployment topology.

**Self-containment requirement:** the control-frame shapes are restated
completely on the page; the council-side check confirms byte-level agreement
with the client's `parseInbound` union, but the page cites no client code.

## Acceptance

- Envelope, seq/ack, and control-frame shapes are restated completely and
  match the shipped client's parser exactly (council-side check).
- The resume/resync handshake, cache-miss path, and fan-out/revocation
  semantics are specified to implementation precision.
- The four-key envelope rule and the only-these-control-frames rule are stated
  as normative with the versioning escape hatch named.
