## Intent

A user on a remote machine sees a `/rc:login` palette row that says only `pi-remote`, then
the attended flow assumes a browser can reach `http://127.0.0.1:<port>/callback` on the remote
host — which it cannot — so the user waits out the timeout and never learns `--headless`
exists. The fix belongs at the surface where the user chooses the command (the registered
description, carrying the condition, not just the token) and at the browser-open failure line,
which must be reachable for that case and name the remedy.

## Acceptance

1. The test harness widening needed to capture `registerCommand`'s `opts.description` is
   declared in the card and the PR (today `test/index.test.ts`'s `command` dep discards opts
   and `test/pi-sdk-load.test.ts`'s strict Proxy does `void opts`); the registered options for
   `rc:login` carry a description whose English text contains `--headless`, asserted at the
   real boundary via the load smoke.
2. Negative pin: the registered descriptions for `rc` and `rc:off` do not contain the
   substring `--headless`.
3. With a failing `openUrl` dep injected, attended login emits
   `login.failure.browserOpenFailed` and does not proceed to the
   `login.attended.waiting`/loopback-`fallback` path as if a browser had opened; the row's
   English text contains `/rc:login --headless`; the byte-diff is named in the PR.
4. If argument completion is added, declaring `getArgumentCompletions` is an explicit R-TYPE-1
   re-diff, not a silent widening.
5. Copy for this card's row and EV-17's wait/cancel copy is settled in one shared design pass
   (card-level constraint).
