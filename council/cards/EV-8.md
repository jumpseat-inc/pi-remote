## Intent

Implements §8 in `src/index.ts` — the entry point that registers commands,
subscribes the live event path (pi.on → translate.ts → transport.ts), and owns
teardown. `/rc` prompts once for a control-plane URL if unset and points the
user at `/rc:login` when no credential exists (EV-7); `/rc:off` (colon
namespace per the owner's decision — never `/rc-off`) closes the WS and
deletes the tunnel; the `session_shutdown` handler tears down for **every**
shutdown reason (`quit`, `reload`, `new`, `resume`, `fork`) so exiting without
`/rc:off` never leaves a live tunnel. User-visible surface — the `/rc`,
`/rc:login`, `/rc:off` command palette entries with their output copy, and the
footer status via `ctx.ui.setStatus("pi-remote", …)` showing exactly one of
seven states in lifecycle order — `off`, `not enrolled`, `authorizing`,
`dialing`, `resyncing`, `live`, `error` (spec §8 authoritative; product-owner
ruling EV-1 Q2 as source). Every state change is a stated sentence resolved
through `loginEnglishFor` (EV-7), never a glyph ack or a raw string.

## Acceptance

- `/rc` on an enrolled host ends with footer status `live` and frames flowing;
  a second `/rc` while connected notifies and changes nothing.
- `/rc:off` while live ends with status `off`, the tunnel deleted at the
  control plane, and a second `/rc:off` is a clean no-op.
- Quitting, reloading, starting a new session, resuming, and forking — each
  with the tunnel live and without calling `/rc:off` — all leave the tunnel
  deleted and the WS closed (one test per reason).
- With no credential configured, `/rc` fails gracefully and its output tells
  the user to run `/rc:login`; footer status is `not enrolled`.
- Footer status is exactly one of seven states in lifecycle order — `off`,
  `not enrolled`, `authorizing`, `dialing`, `resyncing`, `live`, `error`
  (spec §8 / EV-1 Q2); `error` derives only from the typed transport stream
  (EV-3/EV-7), and `resyncing` is shown during a replay (EV-5). A remote
  observer can correlate status with behavior.
- `/rc:login` sets the footer to `authorizing` when the login driver begins
  and returns it to `off` on terminal; the seven-state set has no `idle`
  state (EV-7's success→idle is reconciled to `off` per spec §8).

## Step 6 — product-owner rulings (J1–J5, binding, verbatim)

### RULINGS BEGIN (orchestrator-dispatched product-owner ruling on all five consolidated open-judgment items; no steward deferral)

**J1 — Footer merge policy.** Adopt the kind-first `mergeTransport` with `kind:"live"` clearing a sticky `error`. I amend my own EV-2 Item 4 non-binding preference on this question; the binding parts of that ruling (tunnel.ts ships severity tags; EV-8 owns the final merge rule) are unchanged. The Skeptic verified that a `live` event is emitted only after a successful WS onopen and one-time-token validation, so the failure mode my EV-2 guard was designed against is structurally impossible under the settled seam; the owner's round-0 sticky-until-user position is rejected because it would render a footer that lies about the network at the exact moment a recovered tunnel is honestly live with frames flowing. Operational shape: order-guard; `live → {live, consec:0}` (clears error); most-recent-wins across the live family; `error` reached only by EV-8's threshold-N on consecutive error-severity dialing with the rich reason preserved; `resyncing` is replay-overlay only and never produced by the merge; mid-replay dialing aborts replay and moves footer to dialing.

**J2 — /rc URL-prompt moment.** Adopt Side B: the URL prompt fires only out-of-band after `/rc:login`, never from a bare `/rc`. A bare prompted URL with no tokens is transient by design — readCredential returns null unless serverUrl + accessToken + tokenExpiry are all present, so the URL has nowhere durable to land; storing a serverUrl-only credential contradicts the EV-7 settled boundary (credential = full shape or absent) and would create an enrollment surface with two incompatible shapes. This amends §8's literal "/rc prompts once for a control-plane URL if unset." The amendment rides EV-8's PR per the EV-4 Q1 governance precedent — facilitator-authored, evidence-cited, in-scope prose-sync — because EV-8 owns the URL-prompt surface and the correction preserves the security model (no URL-only credential store introduced) and the user-visible intent (a user without a URL is told to run /rc:login, which is the remedy they need anyway). FLLWUP-1's README-sync carries the user-visible reflection.

**J3 — Enrollment-class 401/403 during reconnect rearm.** Stop the retry loop; the footer lands on `error` carrying the rich enrollment reason (enrollment_expired or enrollment_rejected), and the remedy is /rc:login. This is a different seam from EV-3's retry-forever ruling: that ruling covered transport dial terminality (the WS dial retries transient failures forever because §6 sets no give-up boundary and §8's "terminal" attaches to user-rendering, not the act of retrying). What EV-3 deliberately did not — and could not — cover is credential terminality at the control plane: createTunnel is 401-terminal by design (EV-2 settled; no auto-refresh on a 401 from POST /tunnels), and re-dialing the same dead credential is futile in a way re-dialing the same relay after a blip is not. Transport terminality (dial forever) and credential terminality (stop on dead credential) are two different seams; collapsing them would silently hide the case where /rc:login is the only thing that can unstick the host. The rearm-collapse must-satisfy (transport.ts:359-364) is binding for this ruling: the rearm closure MUST preserve the rich TunnelError.reason end-to-end so the error footer carries the enrollment remedy, not relay_unreachable. The credential-still-present property is unchanged (teardown never clears credential, per EV-2's settled boundary).

**J4 — Exact N.** Pin N = 10 consecutive error-severity dialing events. Both sides converged on ~10; the hard constraints are met (N ≥ 2, injectable as ERROR_DIAL_THRESHOLD, deterministic). The counter resets on any non-error-severity event — a single verified WS open is the system's signal that the dial loop recovered. The counter lives in EV-8's FSM, independent of the transport's backoff counter (those are two different numbers). Trivial to reverse.

**J5 — /rc:login while tunnel is live.** Refuse with a single stated sentence ("close the tunnel first with /rc:off"); footer unchanged; login driver not entered. This is the only resolution compatible with EV-7 general rule 4 — the login driver emits authorizing on begin and off on terminal, so an authorizing → off clobber over a live footer is a composition bug that does not survive a refusal. The same refusal rule applies across all non-idle states (dialing, resyncing, authorizing, error); the driver enters only from off and not enrolled. Side B (allow live re-enroll for credential rotation) is rejected: the apparent rotation cost is one /rc:off keystroke, and the real seam cost — a live re-enroll needs to tear down the live tunnel before driving login, not clear the credential mid-flow, and not collide with the in-flight rearm closure's tunnelId — is three new failure modes for zero user benefit. If a future product call wants live re-enroll, it is a follow-up card that explicitly works rule 4, not a silent extension of it.
