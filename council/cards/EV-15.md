## Intent

The extension should work out of the box against Jumpseat's relay; today a fresh host must be
handed a URL. The default is the last-resort tier — below any stored credential — so a host
already enrolled against a self-hosted relay is not silently re-pointed. The URL prompt is
kept (pre-filled with the resolved value) as the interactive override affordance, and the
resolved relay stays visible at enrollment and in the `<serverUrl>`-rendering surfaces. The
constant needs one home and one resolver rather than three `??` chains (`index.ts:263`,
`index.ts:545`, load-time `index.ts:856`, `rcLoginCommand`).

## Acceptance

1. On a fresh host (no env override, no `piRemote.serverUrl`, no stored credential),
   `/rc:login` presents the URL prompt pre-filled with `https://relay.jumpseat.sh`; accepting
   the prefill (empty submission) enrolls, and the persisted credential's `serverUrl` is
   exactly `https://relay.jumpseat.sh`.
2. Precedence is pinned by test: env → setting → stored credential →
   `https://relay.jumpseat.sh`. A stored credential carrying
   `serverUrl: "https://custom.example"` still dials `https://custom.example/tunnels`, never
   the default; the prompt prefill reflects the resolved tier in each case.
3. The three runtime resolve sites (`rearm` `index.ts:263`, `rcCommand` `index.ts:545`,
   `rcLoginCommand`) consult one shared resolution function so they cannot diverge; the
   load-time value at `index.ts:856` remains the explicit-override-only tier, not the default.
4. With the total resolver, `login.failure.noServerUrl` is unreachable: its emission site and
   copy rows are removed in this PR and the removal is named in the PR description.
5. The `<serverUrl>`-rendering surfaces (footer/error copy) render the literal
   `https://relay.jumpseat.sh` when the default is in force, pinned by test.
6. `AGENTS.md`'s configuration-contract table and `docs/PI-SPEC.md` §7.2 and §8's `/rc` row are
   synced in the same PR.

## 1. Proposed design

**One home — `src/server-url.ts` (+ `test/server-url.test.ts`, per the one-suite-per-module convention):**

```ts
export const DEFAULT_SERVER_URL = "https://relay.jumpseat.sh";

/** Trim; undefined/null and empty/whitespace-only → undefined. */
export function normalizeServerUrl(raw: string | undefined | null): string | undefined;

/** Total resolver. Tier order: env → setting → stored credential → DEFAULT_SERVER_URL.
 *  Total: always returns a non-empty trimmed URL. */
export function resolveServerUrl(input: {
  envUrl?: string | undefined;
  settingUrl?: string | undefined;
  credentialUrl?: string | null | undefined;
}): string;
```

**Dep shape change.** `RemoteControllerDeps.serverUrl: string | undefined` (index.ts:89) becomes `envServerUrl` + `settingServerUrl` (both normalized inside the resolver). The entry passes `process.env.PI_REMOTE_SERVER_URL` and `settingString("serverUrl")` through unchanged — env stays read at the entry only (DI discipline preserved; no env reads inside `src/`).

**Runtime sites:**
- `rearm` (index.ts:263-266): `const serverUrl = resolveServerUrl({ envUrl: deps.envServerUrl, settingUrl: deps.settingServerUrl, credentialUrl: cred?.serverUrl })`; the gate collapses to `if (!cred)` — the `!serverUrl` half is dead. `enrollment_expired` (index.ts:265, 293) now always renders the resolved URL.
- `rcCommand` (index.ts:545-549): same resolver call; the `!serverUrl` branch printing `rc.serverUrlRequired` is deleted, and both copy rows go (`login.ts:268` English table, `copy.ts:73` Indonesian table, plus the key list in `copy.ts`'s header comment and whatever `test/copy.test.ts` pins for the 22-key table).
- `rcLoginCommand` (index.ts:610-617): read the existing credential **before** the prompt (move the `readCredential` at index.ts:618 up), compute `resolved = resolveServerUrl({ envUrl, settingUrl, credentialUrl: existing?.serverUrl })`, then — attended mode — always show the prompt pre-filled with `resolved` ("Control-plane server URL [https://relay.jumpseat.sh]:", exact copy settled in the design pass). **`<serverUrl>`-rendering surfaces (Acceptance 5).** `applyFooter` (index.ts:213) renders `activeHttp?.serverUrl ?? deps.serverUrl`; with the collapsed dep gone it needs the resolved tier. Rather than adding a disk read (`readCredential`) to every footer transition, capture the resolved URL where it's already computed: extend the tunnel variant of `ErrorSource` with the resolved `serverUrl` (every `TunnelError` already carries it — see index.ts:265) and/or a closure-scoped `lastResolvedServerUrl` set alongside `lastRearmReason` for the re-render path at index.ts:~234. ## Cross-seam reading

**What the contract actually is today (verified):**

- The runtime resolve sites are three independent `??` chains over a load-time value that is itself already collapsed:
  - `rearm`: `const serverUrl = deps.serverUrl ?? cred?.serverUrl;` then `if (!cred || !serverUrl)` (`index.ts:263–264`).
  - `rcCommand`: `const serverUrl = deps.serverUrl ?? cred.serverUrl;` then `if (!serverUrl)` → `rc.serverUrlRequired` (`index.ts:545–549`).
  - `rcLoginCommand`: `let serverUrl = deps.serverUrl; if (!serverUrl) inputPrompt(...)` (`index.ts:612–614`), and critically it reads `existing = readCredential(...)` **after** the prompt (`index.ts:617`).
- `deps.serverUrl` is the load-time collapse `process.env.PI_REMOTE_SERVER_URL ?? settingString("serverUrl")` (`index.ts:856`), and `RemoteControllerDeps.serverUrl` is documented as "env > stored credential. May be undefined" (`index.ts:88–89`). So today there is **no** default tier anywhere.
- `noServerUrl` is emitted at `src/login.ts:410–412`, is a `LoginReason` union member (`src/login.ts:52`), has a copy row (`src/login.ts:123–127`) and `rc.serverUrlRequired` has a footer row (`src/login.ts:268`) plus an id overlay row (`src/copy.ts:73`) inside the "22-key" table (`src/copy.ts:77–84` is pinned by `test/copy.test.ts:77–85`).
- Footer `<serverUrl>` substitution uses `activeHttp?.serverUrl ?? deps.serverUrl` (`index.ts:213`) — i.e. the explicit override only. With the default in force and no active dial, `serverUrl` is `undefined` and `renderCopy` **skips the substitution**, leaving `<serverUrl>` literal (`src/copy.ts:118–124`). Acceptance #5 requires the literal default here.

**Proposed design.**

`DEFAULT_SERVER_URL` and `resolveServerUrl` live in a new dependency-free `src/server-url.ts` (mirrors the `copy.ts` precedent; nothing imported, no cycle risk). `src/pi-host.ts` is the acceptable alternative — it already owns host config (`readHostSettings`). One home, one resolver.

```ts
export const DEFAULT_SERVER_URL = "https://relay.jumpseat.sh";

export interface ServerUrlSources {
  env?: string | undefined;        // PI_REMOTE_SERVER_URL
  setting?: string | undefined;    // piRemote.serverUrl
  credential?: string | undefined; // stored credential's serverUrl
}

const nonEmpty = (v: string | undefined): string | undefined =>
  v !== undefined && v.length > 0 ? v : undefined;

export function resolveServerUrl(s: ServerUrlSources): string {
  return nonEmpty(s.env) ?? nonEmpty(s.setting) ?? nonEmpty(s.credential) ?? DEFAULT_SERVER_URL;
}
```

Total return type `string` is what makes `noServerUrl` unreachable. Every tier treats `""` as absent (else `??` short-circuits on empty env and the default never engages).

Wiring. `RemoteControllerDeps.serverUrl` is replaced by the two raw tiers `envServerUrl` and `settingServerUrl` (injected; **not** re-read from `process.env` inside the controller). This is the only shape that lets acceptance #2's per-tier tests avoid env mutation. `index.ts:856` still reads the same two sources and does **not** fold in the default; if a collapsed value is still wanted for anything, it stays `env ?? setting`.

Each runtime site:
- `rearm` (`index.ts:263`): read `cred`, then `const serverUrl = resolveServerUrl({ env, setting, credential: cred?.serverUrl })`; the guard narrows to `if (!cred)`. When `!cred`, pass the resolved `serverUrl` into the `enrollment_expired` `TunnelError`/footer so the relay is named, not `""`.
- `rcCommand` (`index.ts:545`): resolve with `credential: cred.serverUrl`; delete the `if (!serverUrl)` / `rc.serverUrlRequired` block entirely.
- `rcLoginCommand`: move `existing = readCredential(...)` **above** the prompt; `const resolved = resolveServerUrl({ env, setting, credential: existing?.serverUrl })`; then prompt unconditionally with `resolved` embedded in the prompt text as the prefilled value; `const serverUrl = input && input.length > 0 ? input : resolved`. Empty submission = accept `resolved`.
- Footer: cache `let resolvedServerUrl = resolveServerUrl(...)` once in the factory closure (read credential once at construction), refresh it wherever a site resolves, and change `applyFooter` (`index.ts:213`) to `activeHttp?.serverUrl ?? resolvedServerUrl`. That is the acceptance-#5 fix.

`noServerUrl` removal: drop the union member (`src/login.ts:52`), the `FAILURE_ROWS` entry (`src/login.ts:123–127`), the emission guard (`src/login.ts:409–412`), `FOOTER_ROWS["rc.serverUrlRequired"]` (`src/login.ts:268`), the id row (`src/copy.ts:73`), and update the "22 keys" coverage text and the pinned test (`test/copy.test.ts:77–85`) to 21.

## Blind spots

- **The import/pipeline view cannot see the host surface.** `inputPrompt` is typed `(prompt: string) => Promise<string | undefined>` (`index.ts:101`) and maps to `ctx.ui.input(prompt)` (`index.ts:877`). The real SDK's `ExtensionUIContext.input` is `(title, placeholder?, opts?)` (`types.d.ts:75`). **There is no prefill capability on the public surface:** `ExtensionUIDialogOptions` exposes only `signal`/`timeout` (`types.d.ts:37–42`); the interactive wrapper `showExtensionInput` forwards only `{ tui, timeout }` (`interactive-mode.js:2095`); the underlying `ExtensionInputComponent` ignores `_placeholder` (`extension-input.js:26,43`) and its `initialValue` (`extension-input.js:45`) is unreachable through `ExtensionUIDialogOptions`. So "pre-filled with the resolved value" cannot be delivered as editable prefilled text today. The card's own parenthetical — "accepting the prefill (**empty submission**)" — is the tell: the intended semantics is *display the resolved value; empty input accepts it*. That must be rendered in the prompt title (the placeholder is inert), and empty-submit must resolve to `resolved`. A seat that writes "prompt prefill" as if the host supports it is claiming a capability the seam does not have.
- **The frontend/render view cannot see the credential tier.** `applyFooter` has `activeHttp` and `deps.serverUrl` only; it never reads the credential (`index.ts:213`). Acceptance #5 (literal default in `<serverUrl>` copy) is unreachable without a resolved-value cache in the closure — a footer-only fix cannot get there.
- **The data/credential view cannot see that its empty string becomes a dial target.** `readCredential` accepts `serverUrl: ""` as valid (it only checks `typeof === "string"`, `src/credential.ts:224–235`). With a total resolver, a credential carrying `""` now silently dials `https://relay.jumpseat.sh` with a token minted elsewhere. Today that path printed `rc.serverUrlRequired`. This is the one place where "resolver is total" and "credential integrity" collide.

## Reframe

The framing is sound; no cardinal reframe. One bounded tightening: **the resolver must not be the only gate on credential validity.** Treat `credential: ""` as absent in the resolver (consistent with every tier), but tighten `readCredential` to reject an empty `serverUrl` as corrupt (`src/credential.ts:233`) so "no usable URL" surfaces as *not enrolled* rather than "dial the public relay with a foreign token." This keeps the resolver pure and total while keeping the credential store honest about what it vouches for. I would name that as an explicit edge decision in the PR, not silently absorbed.

## Design Position (EV-15, first pass)

**Design position** — Prefilling the `/rc:login` URL prompt with the resolved value is the right affordance: the prompt is the consent moment for *which* server enrollment targets, and a fresh host must see the URL they are about to be enrolled against, not a blank field. Accepting the prefill (empty submission) means "use the resolved URL" — the existing parenthetical at `index.ts:566` ("…or leave blank for PI_REMOTE_SERVER_URL / piRemote.serverUrl") is internal plumbing the user does not need to read and becomes wrong once a default is in force, so it is replaced by a stated sentence naming the resolved URL and the two user actions (Enter to use, type to override). The same prompt always fires (per Acceptance #1); only the prefill and the embedded URL change with the resolved tier — that is the honest way to honor "the prompt prefill reflects the resolved tier in each case" without inventing a different prompt per tier.

**Gulf closed** — Gulf of Evaluation, for a fresh host at the moment they run `/rc:login` for the first time: today the field is blank or shows internal-plumbing hints; after, the field reads "Enroll this host against `<resolved>` — press Enter to use this server, or type a different URL:" — the user perceives which server they are about to enroll against without archaeology, and the "default is Jumpseat's hosted relay" claim is no longer silent. Also closes a smaller Execution gulf for the power user who wants to point at a self-hosted relay: the prompt is the override affordance, the prefill is the suggestion, and an override is one keystroke away in either direction.

**Principle and evidence** —

- **Signifier (what tells the person it is possible)**: the prompt's prefill *is* the signifier for "this is the server that will be used if you press Enter." The current prompt at `index.ts:566` is a parenthetical about env-var plumbing, which is not a signifier of consent — it is documentation of internal plumbing. Replace it with a sentence that names the resolved URL and the two actions, mirroring the existing `tunnel.error.unreachable` English row at `src/login.ts:131` ("Cannot reach `<serverUrl>` — check your network and try again.") which already uses the `<serverUrl>` substitution discipline (FLLWUP-4 OJ5). The prompt becomes a locale-aware copy key — e.g. `login.urlPrompt` — rendered via the same `loginEnglishFor` + `renderCopy` path the error lines use, which keeps it inside the single-vocabulary rule and adds one row to the partial-coverage boundary in `src/copy.ts` (the 22-key table becomes 23).
- **Conceptual model (the wrong model the design must prevent)**: a fresh user must not form the model "blank field = skip / fall through to a hidden default." The current text invites exactly that model. The new sentence forces the model "I am consenting to *this* URL; I may type to override" — the empty-submission semantic change (Acceptance #1) is the forcing function that makes that model correct.
- **Feedback (what tells the person it worked)**: the persisted credential's `serverUrl` is exactly the prefill value (Acceptance #1) — pin that with a test that re-reads the credential file after empty submission, so the user-visible "what server am I on" matches the file on disk.
- **Constraint (a forcing function where the wrong action is costly)**: the prompt is the only step between a fresh host and a credential written to disk against a hosted service; if it is glossed (e.g. "press Enter to continue"), the design has invited the slip. Making it a stated sentence with the resolved URL rendered in-line is the constraint — the user cannot proceed without reading the URL they are consenting to.
- **Knowledge in the world, not the head**: the resolution chain (env > setting > stored > default) is not surfaced to the user — only the *result* is. The user is not asked to know which tier supplied the URL; if they care, they read PI-SPEC §7.2. This honors "stated refusal, never a glyph" (Copy Honesty Doctrine): one sentence names what will happen, the resolution chain is internal plumbing.
